## 接收设计与核对现状

原理图到 PCB 的更新由用户在 EDA 界面发起并确认。AI 不调用 `pcb.importChanges` 或官方导入接口；更新前后用 `pcb.listComponents`、`getComponentPads`、`listNets` 核对器件身份、封装关联、逐焊盘网络和非目标对象。插件回执成功不代替保存重开或整板检查。

## 板框、图层和布局

- `pcb.drawOutline` 的公开坐标以左下角为基准，单位 mil。重复板框前先查实际图元类型和 ID，不预设一定为 Region。
- 层数和层叠分别核对。`setCopperLayers.count` 只接受 2 到 32 的偶数。`getStackingConfig` 读完整配置，`applyStackingConfig` 后重新读回。设默认层叠不等于当前 PCB 已应用；自定义层变更后重新激活 PCB。未知层名或层号不猜测。
- `getCurrentLayer`、物理层叠配置系列和实时 DRC 开关系列在 EDA 4.1.78 实机确认不支持。它们需要 EDA 4.2 或更高版本；4.2 尚未实机验收。逐条名称见[PCB低频指令](commands-pcb-low.md#eda-版本限制)。
- `pcb.moveComponent` 后用 `checkPlacement` 检查间距。后者基于焊盘包围盒，不能代替器件本体、丝印和机械尺寸检查；`complete:false` 或跳过对象不能报告布局全部通过。0.20.63 已在原反馈 USB1 的真实第9个 POLYGON 焊盘核对 `skippedUnsupported`，位号、器件ID、从1开始的padIndex及原因均返回；只读前后电路记录保持，未新增POLYGON碰撞算法。
- `pcb.groupBySchematicRegions` 用于明确要求按原理图功能区整理时。先看 `dryRun`、板框容纳情况和尺寸来源，再执行并读回。它不是普通单件移动的入口。

## 扇出、布线和自动布线

密脚器件位置确定后，先用 `pcb.getFanoutPlan` 检查目标、层、尺寸和 `executable`，再把完整 `data` 作为 `pcb.fanout` 的 `params.plan`。几何范围见[PCB几何命令](commands-pcb-special.md)。

先完成所需扇出，再生成或重建覆铜。多个网络逐个规划、逐个执行，每次执行后重读当前铜面和障碍，避免不同计划使用过期的同一空间。

v0.20.65 候选修复 `pcb.placeVia` 对浮点读回的误报：如 962.648 读回为 962.6480000000001。仅 x/y/孔径/外径使用有 1e-9 mil 上限的机器精度比较，不修改请求值；ID、网络及通孔类型仍严格比较。四项相关回归、类型检查及专家复审通过。EDA 4.1.78原962.648失败样例已正常返回，getter仍为962.6480000000001，输入及原生源码未改值。同一四层样例通过4次placeVia（各请求一次飞线计算）后10次routeTrack：即时及保存关闭重开DRC均为0，全部原始坐标、10.05/7.536 mil线宽和24/12 mil过孔保持。该结果只验证分指令先孔后线流程，不验证SES handler或后补过孔拓扑已修复。

v0.20.68 的 `pcb.placeVia` 后补过孔刷新已通过下述限定安装验收。0.20.67 把原生 LINE 字段误作查询结果字段，实机未选中走线，目标连接错误未消失；该版本验收未通过。修正版从源码 netName/layerId/width 映射内部网络、层和线宽，再与 SDK getter 核对。只选择 SIGNAL 层且 layerStatus 为 1（使用并展示）或 2（使用但隐藏）的普通 LINE；0、缺失及未知状态不选。

创建前读取源码、走线和图层，预选同网且端点与过孔中心一致的 LINE。坐标只容许机器浮点往返误差，不选择线段中部、圆弧或邻近线。过孔创建、读回及飞线请求确认后，每条目标仅提交一次原四端点值 modify，并独立核对原始返回对象 ID、新鲜 getter 和完整源码。不改网络、层、线宽、锁、ID、组或附属记录，不删线重建。刷新期间非 DOCHEAD 记录含 ticket 均须保持；DOCHEAD 仅容许 client/updateTime/version 变化。

无法安全预选或没有相接 LINE 时，endpointRefresh 披露 skipped/reason 并沿用放孔流程。开始刷新后，空返回、抛错、超时、焦点、ID 或源码异常均停止后续刷新，返回 partial:true、retryable:false、过孔 ID、已完成 LINE 和逐条 raw/readback/source 结果。不重试、自动恢复或持续锁定。整条请求共享截止时间，超时不取消 SDK；迟到返回不会继续刷新。

成功回执的 creationTicketChanges 单列创建过孔时旧记录的 ticket 变化；中途失败的 partial 回执暂不含此清单。connectivityVerified 仍为 false，跳过或完成刷新均不是电气连通证明；命令不自动运行 DRC、保存或重开。实机LINE和图层数据加合成边界条件的回归、五项主回归、类型检查、专家复审通过。EDA 4.1.78 的干净两层样例已通过：先画顶层两段和底层四段10.05 mil走线，再放24/12 mil通孔，两个相接LINE的原始modify返回对象与ID、getter和源码保持均核对通过。目标+5V的两项连接错误在保存前消失；保存关闭重开后仍为0，六段走线、一个过孔及全部非DOCHEAD记录保持。另一网络两个原未接焊盘保持，不宣称整板DRC为0。此结论仅覆盖已验普通LINE端点形态，命令仍返回connectivityVerified:false。

人工布线用 `pcb.routeTrack`，换层用 `pcb.placeVia`。先确认网络存在，按电流、规则和板层确定线宽及孔径。`routeTrack` 当前宿主曾出现创建接口返回 ID、但图元未落入文档的假成功；本地候选在共享总时限内逐段调用 `get(id)` 与 `getAllPrimitiveId`，核对 ID、网络、层、坐标和线宽（显式请求或由 `currentA` 换算），同时绑定当前 PCB 焦点。宿主可能合并共线段并改变 ID；只有读回确认覆盖请求几何时才接受 ID 变化。v0.20.58 安装版中，共线延长更换 ID 的样例即时及保存、关闭、重开后均通过，10.05 mil 线宽保持。单段未确认时在 `cause` 保留 `failedPrimitiveId`，并以 `partial:true`、`retryable:false` 报错、停止后续段，不补写、重试或删除。

v0.20.58 安装版按先画 track、再放 via 的顺序测试：过孔读回正确且飞线计算已接受，但两个目标连线即时及延迟仍报 `ConnectionError`；未执行 rebuild。完成组合保存、关闭、重开后错误消失，期间 ID、几何和属性保持。该测试未区分保存、关闭、重开各自的作用，不能称为完全修复。不要自动保存或重开，不要拆线；2026-10-21 在 0.20.62 的干净两器件副本，先放 24/12 mil 通孔再接两层 10.05 mil 走线，目标 +5V 两焊盘的连接错误在保存前消失，保存关闭重开后仍保持；其他网络两处预留焊盘未接线单列。该限定样本可用作先放过孔的操作参考，不代表后补过孔缺陷已修复。`placeVia` 回执 `connectivityVerified:false` 仍不证明跨层连通。`routeTrack` 的 layer 支持 `top`、`bottom` 或数字层ID（含数字字符串），默认顶层；内层须先读回确认已启用，再传实际数字ID，不能把 `inner1` 等铺铜别名直接用于此指令。0.20.65 的 layer:"16" 实机样例已通过几何与保存重开；未知层不猜测。

自动网名如 `$1N1` 可直接作为 `net` 参数使用。其他以 `$` 开头的字面文本可写为 `$$名称`；宏变量仍使用 `$步骤ID.字段`。

## 覆铜和丝印

`pcb.pourCopper` 创建的是边框；用 `rebuildPour` 重建，再用 `listPours` 或 `getPourFillReadback` 确认实际填充。`pcb.listPours(withFill:true)` 的 `fillStatus` 为 `filled`、`empty` 或 `unknown`；`filledRegions` 是 fill 为 true 且路径源通过基础结构检查的区域数，`fillRegions` 是总区域数。仅 EDA 4.1.78 的零宽、已填充且路径采用平坦 L 编码的直线多边形会将 10 mil 单位转换为 mil 并保留原始路径；其他版本或形状不做该换算，原始坐标单位未知。v0.20.58 安装版中，两个平移和尺寸不同的既有 top 填充经 `getPourFillReadback` 读回后保存、关闭、重开，raw 10 mil 到 normalized mil 的换算均正确；扇出覆盖仍未完成。缺少或无效的读回字段会得到 `unknown`。v0.20.51 在 EDA 4.1.78 的1区已填充、0区未填充样例通过保存重开核对；非法返回和全部 fill:false 分支为本地模拟验证。填充状态为 `empty` 或 `unknown` 时不能报告铺铜完成。`rebuildPour` 的 `completed` 不证明填充新鲜、已保存或制造合格。修改边框、优先级或周边布线后再次检查填充；结果不明时停止，不以旧填充冒充本次结果。

局部铜皮先区分 `pour`（随规则裁剪）与 `fill`（固定填充），按[几何命令](commands-pcb-special.md)规划再执行。`modifyPour` 的任意优先级值不保证都可达到，以写后源码读回为准，不据 API 返回值假定成功。v0.20.41 实机中同网 no-op 通过、4 个改网请求写前拒绝；实际改网底层顺序问题仍未修复。v0.20.42 起暂时禁用改到不同网络或不同 `pourName`：当前值须由 source 与 fresh getter 一致确认；若请求变更网络或名称，整条请求写前拒绝，包括混合请求。同网/同名字段本身不写入，同一请求中其他允许属性仍按原规则执行并读回，未请求属性保持原值。layer、width、priority 不在禁用范围；不要求 `toAsync`，也不建议 AI 自动删除再建覆铜作为无损替代。本地回归及 EDA 4.1.78 的改网/改名写前拒绝、同值不写和允许的优先级修改保存重开已按限定样例通过；底层改网/改名顺序问题未修复。

`pourCopper` 可选 `net` 指定新建覆铜网络；`preserveSilos` 仅接受布尔值，省略时保留 SDK 默认行为。命令仅创建覆铜边框，不自动重建或填充。EDA 界面手动新建或修改仍可操作，但要核对排序、执行重建并读回实际填充。读回不符时按部分结果报告并保留已创建边框 ID；现场核对前不重试或删除。不要把删除旧边框再新建宣传为无损改网或改名。`preserveSilos:true` 的单次实机样例三方输入一致并读到 4 个 fill，但保存重开后的 POURED/连接检查未通过，不能据此报告成功；详见[更新记录](https://github.com/quhuii-lgtm/easyeda-aicommand/blob/main/CHANGELOG.md)。

v0.20.40 `pourCopper` 路径候选仅接受单 R 的一维路径或恰好一层包装，并严格核对 7 项相等；多环、额外嵌套或参数变更应拒绝。详细诊断为 raw 与 normalized 输入；候选本地定向检查通过，统一回归和新版宿主待验。

`placeString`、`modifyString` 后检查可读性、镜像、方向、焊盘遮挡及板边。网络丝印仍须通过计划命令，并检查实际图面。

## 检查、保存和生产导出

布线与覆铜后运行 `pcb.runDrc`；定位具体问题时用 `runDrcDetailed`。两条命令遇到非数组结果会报“结果不可判定”，不能按 0 项通过处理。仅 EDA 4.1.78 的 `runDrcDetailed` 会同时返回按 10 mil/单位换算的 `xMil`/`yMil`，并保留原始 `x`/`y`；其他或未知版本只看原始坐标，单位未知。v0.20.58 安装版实测中，`x`/`y` 乘以 10 mil 与返回的 `xMil`/`yMil` 对应。使用违规坐标前先与同一对象的 PCB 读回位置对照。DRC 不覆盖器件本体、全部机械或制造要求。`runDfm`、`runSmtDfm` 与同网焊盘间距检查的材料、单位及覆盖范围见[下单检查](commands-pcb-special.md)。检查未完整覆盖时不报告通过。

各阶段保存后核对目标与非目标对象。需要证明持久性时，关闭重开后再次读回。Gerber、贴片坐标和网表导出后还需检查文件对应的 PCB 版本、格式、单位和实际内容；见[网络与导出](commands-pcb-special.md)。

`pcb.exportPickPlace` 的 `fileType` 仅支持 `xlsx` 或 `csv`，默认 `csv`；`unit` 仅支持 `mm` 或 `mil`，默认 `mm`。导出后核对文件内坐标与单位，不能只看返回成功。

删除前查目标图元 ID 并备份。代理文件备份按工程保留最近 5 份，各 PCB 共用上限；代理不可用时回退到扩展存储的固定单键，跨工程和 PCB 共用，后一次会覆盖前一次，只留最近 1 份。`pcb.delete` 会在启动任务前拒绝空 ID 列表或空白 ID；读回未知时停止后续删除。`pcb.sourceRollback` 仅用于确认需要恢复的备份，恢复前核对 PCB UUID，恢复后读回并保存。关闭页签不等于可靠回滚。

破坏性操作失败后，插件在 500 ms 内核对当前焦点、文档 UUID、文档类型和完整源码。只有确认原内容未变时才跳过 `setDocumentSource`，但仍报告操作失败；`cause` 标记 `restored:true`、`contentRestored:true`、`noRecoveryWriteNeeded:true`、`retryable:true`，并保留 `operationError`、`recovery` 和 `normalizations`。检查超时或结果不确定时，继续原整页恢复流程；源码比较仍包含 POURED。此行为是本地候选，宿主验收待完成。

v0.20.57移除SES导入恢复失败后持续拒绝同一PCB的文档锁。本次失败仍报告partial、restored及诊断；后续独立请求重新执行常规身份、输入、几何和读回检查，不自动重试旧请求。此前暂停的自动回灌、覆铜改网/改名、指定焊盘直连及版本限制不因此恢复。

## 圆角与部分扩展完整写入（0.20.73，限定实机验收通过）

### 指定路径差分走线（0.20.79候选，安装版待验）

`pcb.routeDiffPair` 按中心路径生成正负两条耦合折线。调用前查询当前窗口help。`pair` 明确提供 `{positiveNet,negativeNet}`，两个网络必须存在且不同。`path`、`width`、`gap` 使用mil。gap是铜边距离，中心线距离为width+gap。

正侧按路径前进方向的数值法向 `[-dy,dx]` 偏移，负侧反向。屏幕视觉左右取决于坐标方向。反转path会交换两根线所在的空间侧，不会交换输入网名。

先用 `dryRun:true` 读取并预览；省略或false时执行写入。指定层须为已启用SIGNAL层。只删除几何等价的连续重复点和同向共线中间点，不吸附或拉长输入。生成段沿用最短1mil；反转、自接触、正负任意段间距不足或数值不可靠时，整对写前拒绝。

两侧共用文档与时间预算。逐段读回，并核对最终源码覆盖、非LINE记录和规则保持。中途失败返回partial及已完成侧和失败候选证据，停止后续步骤；超时不取消宿主操作，不重发、不自动删除或回滚。后续独立命令不受持续锁定。

`plannedLengths` 只表示本次计划路径，不是整网实测长度。转角造成的两线长度差会明确返回。该命令不自动避障、蛇形调长、并联重复焊盘或建立差分规则，也不自动保存。成功后仍按项目要求核对实际连通、全板DRC、参考面和长度差；不从创建成功推断阻抗合格。

```json
{"cmd":"pcb.routeDiffPair","params":{"pair":{"positiveNet":"USB_DP","negativeNet":"USB_DM"},"path":[[100,100],[300,100],[500,300]],"width":6,"gap":4,"layer":"top","dryRun":true}}
```

示例数值仅演示参数，不是USB设计参数。生产线宽/线隙应使用同一份有来源的叠层和计算记录，与规则及实际订单核对。差分等长容差按具体接口要求确定，不默认套用10mil。

### 蛇形补长（0.20.80候选，安装版待验）

`pcb.tuneLength` 在指定区域给开放走线链补长。`net`、`targetLength`、`region:{xMin,yMin,xMax,yMax}` 使用当前PCB的网络和mil坐标。`targetLength` 是所选链的中心线总长，不是整网所有支线的长度之和。

按D12优先使用可确认适用的项目规则。当前SDK没有可靠的局部蛇形容差、自间距读取接口，因此必须明确填写 `lengthTolerance` 和 `minSelfGap`。前者是累计总长误差，后者是涉及新增蛇形的非相邻线段铜边间距，不重新要求两段未修改旧线达到此值。不得用差分gap、差分默认10mil或网络相对长度容差代替。几何读回容差0.001mil与累计总长容差分别使用。返回parameterSources说明显式参数与当前未确认适用的规则映射，不声称已从工程自动取得数值。

目标已经在总长容差内时返回changed:false，不写入。目标更短且超出容差时明确报错。生成线段沿用最短1mil要求。原线中途接有支线、焊盘或过孔时，必须确认连接会保留；不能确认则写前说明对象及原因。特殊外形、跨层范围或覆铜实际接触不明时不猜测。

执行时先创建新局部路径并读回，确认原线和非目标记录保持，再删除明确的原调节段，最后核对枚举、源码及实际总长。失败可能返回partial、新线ID、删除尝试和旧旁路状态；unknown表示无法确认。此时停止依赖该结果，不自动重试、回滚或保存，后续独立命令不受持续锁定。

返回的计划长度和实际长度仅针对本次选中链。实际最小间距如实报告，不夹到请求值。成功不代表全板间距、连接、阻抗或制造通过；仍需按具体接口及实际叠层核对。Type-C重复脚分支与自动布线流程另行开发。

参数示意：选中一条200mil测试直线，目标220mil，明确提供lengthTolerance与minSelfGap，再dryRun预览。示例长度和容差由测试目的选择，不能当作USB、DDR或其他接口的默认设计参数。

## 自动布线结果取回（0.20.87，限定只读取回通过）
