# 原理图 4 · 整页验收与交付

按[连接与环境](setup.md)确认窗口、工程和图页。具体参数、默认值和回包查目标窗口的 `__help`。

## 修改和批量操作

修改、删除、异常恢复与保存读回按本阶段步骤执行。

- 器件移动、旋转或镜像后，重新读取引脚端点。
- 旋转后以 `schematic.listPins` 读回的实际引脚坐标和方向规划连线，不按位号或旋转角推断朝向。
- 纯排版修改应保持电气连接和器件参数不变。
- 修改共享导线前，查清全部分支和范围外接点。
- 替换器件时重新检查整组属性和装配状态。
- 专业版改值可能清空供应商编号，随后重新核对料号。
- 导线分段数量不能代替网络连通检查。

## 修改前后差异检查

按本阶段步骤比较修改前后的器件属性、网络与位置。纯排版须保持连接和参数不变；电气修改逐项对应需求。无法解释的差异列为待验证。

## 原理图完成检查

先明确工程、图页、功能区和本轮改动；只验本轮及受影响接口，局部改值不要求重新验收整图。按确认的功能区清单、器件表和连接表检查，不能只写“已按技能完成”。

## 验收项目、方法和通过条件

| 项目 | 怎么验 | 通过条件 |
| --- | --- | --- |
| 功能分区 | 对照功能区清单，用 `listRects` 核对框的 ID 和 `span`，用 `listTexts` 及最新局部图核对标题、内容归属和区框位置。 | 每个计划功能区有实际框和可读标题，内容归属正确，框不重叠；不能只比较框总数。 |
| 器件和布局 | 对照器件表读回型号、参数、料号、位号、脚号、极性、封装及装配属性；查看每区放大图和真实脚位。 | 属性及多单元对应正确；支路和去耦靠近所接引脚，符号、位号、参数、标题无遮挡。 |
| 接线画法 | 用 `listPins`、`listWires` 和最新局部图核对端点、路径、连接点、出线方向及标签；旋转或镜像后重新读脚位。 | 区内相近同网按要求直连，包括 GND；长线和跨区使用适当标签，不穿符号、其他引脚或 NC，不留多余尾线。 |
| 直连长度 | 网格已知时累计全部折线段；分支按所有端点对的最短路径中最长值检查，不逐段套用长度限制。 | 满足默认40格和避让要求；网格未知时说明采用的估算及图面核对，长度条款标为未完成，不能冒充精确检查通过。 |
| 实际连接 | 对照连接表逐项比较“位号＋脚号→网络”和网络成员，用 `getNetlist` 核对实际连通，用 `listNetLabels` 核对附着及网名；NC按引脚属性或当前有效源码确认。 | 应接、禁接、NC、连接器针序和电气类型符合要求；无漏接、误接或意外并网，不能只比较网名是否存在，也不能把网表未出现的脚当作已设NC。 |
| ERC/DRC与结构 | 运行 `runDrcDetailed` 及适用的 `structuralAudit`，记录检查图页和范围，逐条核对错误、告警、排除对象及碰撞候选。 | 无未解决错误；其余告警已修复或按项目已确认的处理方式记录。候选未看图、返回结构未知或检查不完整时不判通过。 |
| 图面和保存 | 查看修改后每区放大图及整页图，确认分区和阅读顺序；按下节保存并核对实际保存内容。 | 局部及整页检查完成，保存对象与验收对象一致；旧截图、整页缩略图、调用成功或DRC为0均不能代替检查。 |

- 方案要求的烧录入口、测试点和0Ω可拆连接逐项核对；不适用时注明，不额外增加电路。
- 结构审计只作筛查，不能证明没有漏画分区或全部视觉问题合格。
- 图面合格和电气连接正确分别判断，两者不能互相代替。
- 不通过或未完成的项目先修正、补查；只重查受影响项目。规则变更后重跑受影响检查。
- 不取消 BOM、PCB 包含状态或检查规则来隐藏问题；无法解释的范围外差异列为未完成。

## 逐块自检与跨页复验

保留脚本原始候选。复核后在读回 JSON 的 `candidateReviews` 记录 `key`、`status`、`reason` 和 `evidence`。用报告中的 `candidateKey` 关联具体项。确认可保留时填 `retained`。已返工时填 `fixed` 并重跑。原项仍出现时继续处理。标注避让用重开后的局部图核对。

## 替代器件复验

原库件无法使用时，先按项目约定确认替代范围。按原图核对所有引脚的网络和 NC。核对同一封装内的焊盘编号及对应关系。保存重开后重查网表、封装、BOM／PCB 属性和符号显示。

在设计和读回 JSON 的 `substitutions` 各填 `ref`、`footprint`、`evidence` 和 `pins: [{ pin, pads }]`。使用完整引脚 ID 和焊盘编号，焊盘号使用字符串数组。设计填原图及封装证据，读回填重开证据。读回另填 `display`（`unchanged` 或 `changed`）和 `displayEvidence`。位号、BOM／PCB 属性仍在 `components` 核对。脚本分开报告资料缺失、电气差异和外观候选。

封装使用两端可比较的已核对标识。库和项目的 UUID 不同时，先核对封装和焊盘几何，再用一致的封装标识。

## 整页复验

若本轮删除独立文字，在设计的 `deletedTextIds` 记录目标 ID。重开后将本页完整 TEXT ID 列表写入读回的 `reopenedTexts: { pageId, ids, evidence }`。旧 ID 仍在时脚本报失败。保存前的删除回包只用来核对即时结果。

每个功能区完成后，必须用 [check-schematic.mjs](../../scripts/check-schematic.mjs) 验收。以 `stage: "wiring"` 检查该区的预期与最新读回，并核对局部图。保存该区报告，修正失败项并补齐必检项后再通过。
页面所有功能区通过后，必须以 `stage: "sheet"` 对整页的预期与读回再运行一次脚本。结合整页图、DRC 和保存重开证据复验，再按项目约定提交页面验收。
涉及跨页连接时，保存后关闭并重开涉及的图页。按图页 ID 逐页读取宿主网表，核对全部跨页网的成员集合。
成员用位号和脚号标识。逐网查漏接、多接和串网，保留每次读回来源。只有项目完整网表时，可逐页读完整网表并比较全部网络。

沿用 `layoutPlan` 时，整页读回 JSON 填 `blockReviews: [{ id, status, evidence }]` 和 `sheetReview: { status, evidence }`。
通过填 `pass`，失败填 `fail`，缺少记录留为未完成。`evidence` 填实际读回及图面的引用。
设计 JSON 用 `crossPage: { pageIds, nets }` 列出涉及页和独立预期网表。读回 JSON 用 `reopenedPages: [{ id, evidence, nets }]` 保存逐页重开后读取结果。
两边的 `nets` 都用 `[{ net, pins }]`，`pins` 为位号与脚号列表。预期和实际须覆盖相同范围，并保留实际读回中额外出现的网络或成员。
若宿主自动生成的网名不稳定，按独立预期的完整成员集合匹配后统一名称。保留原始读回，无法唯一匹配时按差异报告。
脚本检查所提交的记录及网络成员差异。执行者仍须核对图面、DRC、重开过程和读回来源。

## 保存与重开范围

- 新绘整图或整图正式交付：写入结束、保存确认后，关闭并重开受影响图页，核对图页身份、关键器件属性、网络、分区及标题和最新图像；这些内容应与保存前一致。
- 普通局部改值、文字或位置：核对目标及受影响的连接、属性和图面，保存并确认当前版本；不要求为此重开整个工程。
- 局部涉及删除、更换器件、连接重建，或用户明确要求持久性检查时：保存后重开受影响图页，读回对应对象和网络；同时核对非目标内容保持。
- 未重开只报告“已保存，未验证重开”；重开后实际核对过才报告“保存重开已验证”。写入或保存结果未知时先核实原操作，不强行关闭或重发。

## 验收结果怎么报

用一张简表报告，范围外项目标为不适用并说明原因，不粘贴全部原始回包。

范围：工程、图页、功能区和本轮改动。

分区、器件布局、接线、长度、实际连接、规则、图面和保存分别列行；涉及多个功能区时注明对应范围。

| 项目及范围 | 结论 | 检查依据 | 未解决或未完成项 |
| --- | --- | --- | --- |
| 功能区／验收项目 | 通过／不通过／未完成／不适用 | 对象读回、网表比较、实际查看的图像及范围，或告警处理结果。 | 具体问题或缺少的检查及原因；无则写无，不适用时说明理由。 |

保存项写明“已保存，未验证重开”或“保存重开已验证”及实际核对内容。最后给整体结论；任一适用项不通过则整体不通过，任一必检项未完成则不能报告整体通过。

## 转 PCB

- 核对工程、板子、原理图、目标 PCB 和装配版本。
- 专业版同步时，原理图和 PCB 必须属于同一个板子。
- 同步前保存，并检查变更清单的勾选项。
- 需要转移规则时检查“包含设计规则”和具体选项。
- 执行“应用修改”后再检查结果。
- 逐个核对器件、位号、封装、焊盘网络和针序。
- 不把不同板子或装配版本合成一份生产清单。
- 已布线 PCB 改网后，检查旧走线、过孔、分支和铜面。
- 按影响重建铺铜并重新检查。
- 同步成功不能证明旧铜线已符合新网络。

## 删除、修复与结果未知

- `schematic.delete` 前核对目标 ID 与依附关系，删除后重新扫描。长任务用 `task.get` 查询；超时不代表取消。任何写入结果未知时停止后续写入。确认持久性需保存、关闭、重开，再核对身份、属性、网络和非目标内容。

- 删除 TEXT 使用正式删除接口并核对源码和模型；当前已知即时删除后保存重开可能以原 ID 复活。`directDeleted` 不代表持久删除。返回未知或读回不完整时停止，不改用整页源码写回，不重试或补偿写入；help 标明持久性限制，不据此禁用全部删除路径。

## 检查、网表和导出

- 用 `schematic.listNets`、`schematic.listWires`、`schematic.getNetlist` 或 `schematic.exportNetlist` 核对预期网络和引脚，再运行 DRC。
- `schematic.runDrc`、`runDrcDetailed` 和 `buildBlock` 的收尾 DRC 结果遇非数组或未知结构时不可判定，不能视为通过。`buildBlock` 为完整功能区生成内容，不替代器件与连接逐项核对。
- EDA 4.1 的 `listNets` 可借 PADS 网表和命名导线回退列出自动网络名，但 `detail:true` 不保证将无网络名导线归属到自动网；用 `getNetlist` 检查引脚。点和区域图元查询需 EDA 4.2 或更高版本。
- `schematic.getNetlist` 的 JLCEDA 格式走文件生成通道，可能更新位号、Unique ID 或保存工程。失败后先读回，不自动回退或重发。网表非空仍需解析核对。
- `schematic.exportNetlist` 也可能更新位号、Unique ID 或保存工程。用 `schematic.exportBom` 后，按返回的实际格式解码并检查文件。
- 保存后可用 `schematic.exportPng` 检查整页；按返回文件实际类型解码，多页结果可能为 ZIP。后台 `editor.screenshot` 可能是旧帧。若两次审计数量不一致，等拓扑刷新后重查。DRC 或结构审计结构未知时结果不可判定，不能视为通过。
- `schematic.modifyText` 在 EDA 4.1.78 被拒绝；此接口需要 EDA 4.2 或更高版本，4.2 保存持久性尚未确认。不要把即时读回当作已保存。

## 异常修复和宏

- 先只读定位标签异常，再按情况用 `pruneFloatingLabels`、`fixNetLabels`、`repairNet` 或 `dedupeWireNets`。支持 `dryRun` 时先预览；`pruneFloatingLabels.dryRun` 省略时执行清理，`fixNetLabels.dryRun` 省略时只预览。修复后核对网表和 DRC。源码改写兜底不是普通修复前置，只有明确需要且已备份时使用。
- `macro` 仅组合已确定且中途无需判断的步骤；步骤结果键为 `steps`。遇到失败或未知写入时停止依赖步骤。需要根据读回决定下一步时，分开提交。

完整器件替换不是单条 ACE 指令。替代型号、封装和引脚映射须先由 AI 与人工确认；模块复用插件的 RPC 不属于 ACE HTTP 指令。仅用 ACE 时，应先备份工程，核对新旧器件资源、逐引脚映射、网络和属性，再放置新件；全部确认后才删除旧件，并复查网表和非目标对象。PCB 更新由用户在 EDA 界面发起并确认。

官方网表接口：[旧字符串接口](https://prodocs.lceda.cn/cn/api/reference/pro-api.sch_netlist.getnetlist.html)、[文件接口](https://prodocs.lceda.cn/cn/api/reference/pro-api.sch_manufacturedata.getnetlistfile.html)。
