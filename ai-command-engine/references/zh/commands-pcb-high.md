# PCB高频指令

这里的“高频”是按常见绘板流程推荐，并非调用次数统计。先按[连接与环境](setup.md)核对目标窗口。`GET /help?cmd=<命令名>` 使用代理当前选中的窗口；确认它与目标版本一致后再用返回的参数。完整限制见[PCB详细说明](commands-pcb.md)。特定规则、层叠和专题操作查[PCB低频指令](commands-pcb-low.md)。

| 阶段 | 推荐指令 | 作用 |
| --- | --- | --- |
| 看现状 | `pcb.listComponents`、`pcb.getComponentPads`、`pcb.listNets`、`pcb.listLayers` | 确认器件、焊盘网络和图层。 |
| 焊盘连接方式 | `pcb.connectComponentPadDirect` | 兼容入口暂时停用；调用会在访问工程或 SDK 前拒绝。 |
| 布局与板框 | `pcb.moveComponent`、`pcb.checkPlacement`、`pcb.drawOutline` | 先按[PCB操作要求](PCB操作要求.md)规划布局，再摆放、查间距和建立板框。 |
| 布线 | `pcb.routeTrack`、`pcb.placeVia` | 按[PCB操作要求](PCB操作要求.md)规划走线与换层。`routeTrack` 暂行插件政策要求每段至少 1 mil（25.4 μm），短段写前拒绝；不是 SDK 限制。 |
| 铺铜 | `pcb.pourCopper`、`pcb.listPours`、`pcb.rebuildPour` | 建立、检查和重铺铜区。 |
| 检查 | `pcb.runDrc`、`pcb.getNetInfo` | 检查规则和目标网络。 |
| 保存与生产 | `pcb.save`、`pcb.exportGerber`、`pcb.exportPickPlace` | 保存并按需生成生产资料。 |

表中列出常用入口。PCB 坐标和长度使用 mil。`routeTrack` 的返回 ID 不单独证明线路已写入；应以图元读回为准，细节见[PCB详细说明](commands-pcb.md)。`pourCopper` 只建立覆铜边框；用 `rebuildPour` 检查实际填充，结果为 `no-fill` 时不报告铺铜完成。DRC 无错误不能单独证明可生产。

`pcb.connectComponentPadDirect` 名称和参数保留以兼容现有调用。必填 `documentUuid`、`componentId` 和 `padNumber`；可选 `padId` 用于区分同号焊盘。

命令当前始终抛出暂时停用错误，`error.cause` 为 `{ disabled:true, retryable:false, writeAttempted:false }`。拒绝发生在任何工程或 SDK 访问之前，因此本次调用没有执行读写，也不会返回 `partial` 写入结果。

暂时停用的原因是当前实测宿主的公开接口无法可靠读回热焊配置；这不代表整个宿主版本的所有 setter 均失效。待有可靠读回接口或官方修复后再评估恢复。`pcb.getComponentPads` 的只读诊断仍可用，布线、复制图页和模块复用不受影响。

`pcb.getComponentPads` 的 `heatWelding` 是逐焊盘只读诊断，状态区分 `null`、`config`、`unavailable`、`exception` 和 `invalid`。读取异常返回 `{status:"exception",error:{message}}`；无效返回值返回 `{status:"invalid",returnedType,reason}`。`config` 只表示读到配置，不证明规则优先级或宿主实际采用的连接规则。

`heatWelding.status:"invalid"` 时还带 `rawFields`，固定列出 `connectionMethod`、`divergenceSpacing`、`divergenceLineWidth` 和 `divergenceAngle`。每个字段独立返回 `status` 与 `type`；安全标量才返回 `value`。未定义、读取异常分别标为 `undefined`、`exception`。非有限数值只附 `finite:false`。对象、函数、Symbol 和 BigInt 只记录类型，不读取任意字段、不转换或序列化。每个 SDK 字段最多读取一次；该诊断不改变无效判定或直连写入行为。

`pcb.connectComponentPadDirect` 的可选 `_timeoutMs` 默认 290000 ms，最大 2147483647 ms；低于 1000 ms 的预算按 1000 ms 计算。

## 位号与丝印预检查（0.20.71限定实机通过）

`pcb.modifyComponentAttribute` 修改器件的 Designator 属性文字。用 `componentId` 或唯一的当前 `designator` 定位，支持 `x`、`y`、`rotation`、`fontSize` 和 `visible`。坐标单位为 mil。它保留位号文本、器件位置、封装和网络；不能用它重新编号器件。只传需要修改的字段。成功前会核对属性 getter 与完整源码；命令不自动保存。

`pcb.checkSilkscreen` 的原设计侧只读检查可取得 SDK 世界包围框的独立文字、位号与焊盘；0.20.74另增下文制造图层检查。`minClearance` 单位为 mil，默认 0。返回 `potentialConflicts` 表示包围框重叠、相接或接近的候选，不代表已经确认真实字形碰撞。`sdkBoxDistanceMil` 不是实际丝印到铜或阻焊的净距。

检查结果的 `complete` 固定为 false。结合 `checkedObjects`、`coverage` 和 `unsupported` 判断实际覆盖；没有候选也不能报告整板丝印合格。原设计包围框侧未覆盖封装内部丝印、实际阻焊开口、复杂板框及字体笔画边界；制造图层的独立覆盖见下文。编辑器隐藏图层不代表生产时不输出，不能据此跳过检查。

两项功能已通过本地回归、专家复审，以及0.20.71顶底位号修改、文字移动/换面和保存重开检查；丝印覆盖仍有上述缺口。仅在当前窗口 help 已列出对应命令时调用。

## B3 孔与独立焊盘候选（安装版待验）

`pcb.placeHole` 的 `x`、`y` 和 `holeDiameter` 单位为 mil；必须明确 `plated`。`plated:false` 且不提供 `padDiameter` 时创建无铜机械圆孔。提供 `padDiameter` 时创建带铜盘的多层焊盘，盘径必须大于孔径；`plated:true` 必须提供盘径。纯机械孔不能绑定网络。孔径由设计要求与制造能力确定，不从螺钉名称猜尺寸。

`pcb.placePad` 创建独立表贴焊盘；必须指定 `layer:top|bottom` 及 `shape:circle|rectangle`。圆形提供 `diameter`；矩形提供 `width`、`height`，可选 `cornerRadius`。它不创建器件或钻孔。

0.20.86 已在 EDA4.1.78 验证新网默认记录适配。创建 PAD 时，宿主可能同时生成该网络的默认 NET 和规则记录；插件仅接受精确对应本次请求且内容为已确认默认值的两条记录，其他图元与已有规则仍须保持。无需预先创建网络。普通 SMD 新网创建及保存重开通过；带铜孔和部分阻焊的新网分支仅完成本地回归。

焊盘的可选 `solderMaskAndPasteMaskExpansion` 使用 SDK 数值字段 `topSolderMask`、`bottomSolderMask`、`topPasteMask`、`bottomPasteMask`，单位为 mil。完全省略对象时按源码确认继承，另返回 getter 的当前有效值；只给部分字段按下文0.20.73候选的创建时默认值快照处理；不把这次读到的数值写成制造默认值。显式字段同时核对源码与 getter。`solderMaskOpen` 不受支持。

机械圆孔仅对已核对的多层实心圆接受请求线宽0被宿主保存为1的表示差异，并单列请求值与实际值；圆心与半径仍须一致。它不适用于任意Fill路径。返回的 `manufacturingExportVerified:false` 表示本次命令没有执行制造导出，不能用历史夹具导出来代替当前对象检查。

成功前会按ID读取新对象并检查完整源码；允许且报告宿主重新编号ticket，不允许非目标图元或规则内容随意变化。命令不自动保存、运行DRC或导出制造文件。出现未知写入时保留已创建ID并停止，不自动补写、删除、重试或持续锁住后续独立请求。正式安装版及各形态的保存重开仍待验。

### 0.20.71 实测与后续候选

0.20.71的三种圆孔已通过正式指令即时读回和钻孔导出；顶底位号修改、隐藏显示及丝印候选随移动/换面变化也已实测。保存关闭重开后，相关图元完整数据保持，B2仍仅是包围框预检查。

本版矩形PAD在源码radius字段处误报，小数圆PAD在getter一位小数表示处误报。原请求没有重发；完整源码及制造导出证明已创建的矩形尺寸与显式扩展、小数圆PAD尺寸和位置正确，保存重开保持。0.20.72修正这两处适配，正式指令仍需新位置复验。

仅对PAD的X/Y和ELLIPSE宽高，允许getter精确值或确定的一位小数表示。几何成功仍要求完整源码精确符合原请求，其他字段与非目标数据也必须通过检查。返回兼容字段及真实getter/source，不以近似getter补足源码缺失或超时，不写回舍入值。负数、边界和其他形态的完整舍入行为没有全部实测，不扩大到孔径、偏移、角度、mask或Fill。

## 旧0.20.72孔与焊盘问题记录

非零矩形圆角存在单位映射错误：公开cornerRadius声明为mil，当前宿主SDK按短边半长的百分比处理第四项。源码/getter相同不证明制造半径正确。0.20.73候选已包含转换，正式指令尚待实机复验；零圆角与圆焊盘的独立结论不受影响。

部分指定solderMaskAndPasteMaskExpansion时，未给字段的null在保存重开后会变成0，不能称可靠继承。修复验证前，使用完全省略扩展对象或完整四字段的已验模式；不把部分对象即时读回当成持久性验收。拟验证方案为读取新焊盘当时的有效默认值、合并指定字段后完整保存；这会固定创建时的数值，以后全板规则变化不会自动更新这些字段。该方案的隔离试验现已通过；0.20.73正式接入候选仍待实机验收。

## 圆角与部分扩展完整写入（0.20.73，限定实机验收通过）

矩形 `cornerRadius` 使用mil，范围为0到短边的一半。当前已验证宿主的SDK圆角值为短边半长的百分比，插件传入 `200 × cornerRadius / min(width,height)`；回执分别保留 `requestedCornerRadiusMil` 与 `sdkRadiusValue`，不能把SDK数值当成mil。制造检查需核对实际使用的圆角光圈及位置，不能只看getter或源码参数。

完全省略 `solderMaskAndPasteMaskExpansion`，或传空对象 `{}`，使用宿主继承模式。完整提供四项时直接使用所给数值。

只提供部分字段时，插件先以继承模式创建新焊盘，读取该焊盘的四项实际有效值，再与指定字段合并，只修改同一新ID的扩展属性。返回 `mode:explicit-with-default-snapshot`、原始 `requested`、`defaultsReadback`、最终 `applied` 及 `defaultedFields`。未给字段会固定为创建时读到的数值，以后修改全板规则不会自动更新；插件不猜默认值，也不把null补成0。

创建后、修改前、修改后分别检查图元身份、几何、源码和其他记录；默认值无法完整读到、状态改变或修改结果未知时停止，不自动重发或删除。失败回执保留创建ID、阶段和已取得的默认值/应用值。成功仍不代表已经保存或完成制造检查。

当前EDA4.1.78的隔离试验已验证：默认值来自本次getter，覆盖顶层后其余值保持，保存关闭重开四项保持，40mil圆PAD的3mil顶层扩展输出46mil开口。这个试验不等同正式命令安装版验收，也不证明任意后续规则求值或其他版本的圆角语义。

### 0.20.73正式指令限定实机验收

EDA 4.1.78 的独立测试工程已验证：顶层60×40mil和底层40×60mil矩形的公开5mil圆角，实际使用的制造光圈均为R5mil；SMD及金属化孔只提供顶层阻焊3mil时，读取当次默认2/2/0/0，完整保存3/2/0/0。空对象保持四项null继承，已有+5V网络保持。新SMD铜40mil、顶层阻焊46mil、锡膏40mil；PTH铜60mil、孔30mil、顶/底阻焊66/64mil均已核对制造输出。保存关闭重开后193条非DOCHEAD设计记录data完全保持。默认值只代表本次工程读回，不是制造默认值；此为独立夹具的限定验收，不代表整板制造通过或其他宿主版本已验收。

## 丝印制造图层检查（0.20.75限定实机验收通过）

`pcb.checkSilkscreen` 同时返回原设计的包围框候选和 `manufacturing` 制造图层检查。调用不改图、不保存，也不自动裁切丝印。

原设计侧的 `potentialConflicts`、`checkedObjects`、`unsupported` 和 `coverage` 保持原意，顶层 `complete` 仍为false。它们不能确认真实字形或阻焊碰撞。

`manufacturing` 使用本次官方 Gerber 导出的顶/底丝印、同侧阻焊开口和支持的板框。封装丝印和字体使用实际导出坐标，底层不再做镜像。确认问题与数值边界候选分别返回。`minClearance` 是调用方指定的mil间距，不是自动读取的板厂规则。

首版解析已核对的毫米绝对坐标格式、圆光圈直线笔画、圆/矩形/已确认圆角宏闪绘、填充区域和顺序绘制/擦除。圆形近似使用内外区域并披露误差；接近判定边界时保留候选。未知指令、宏、圆弧或不明板框会明确标记相关层未完整解析，不能据此报告通过。

板边首版只覆盖角色明确的单一简单闭合直线轮廓，同时查板外和边距；多轮廓、槽孔角色和复杂曲线未覆盖。板框描线宽度不作为板材边界宽度。

制造文件可能已被宿主裁切丝印。制造图层未发现问题不证明原设计没有压盘；仍须结合原设计候选查看。合并后的图层不能反推出两个丝印对象之间的碰撞或原始对象ID。`manufacturing.complete` 只说明所列导出层的解析和检查范围，不是整板可制造结论。

## 丝印只读源码重排适配（0.20.75）

EDA4.1.78实测在只读丝印检查后，193条设计记录data保持，但对象键、器件PAD_NET行顺序和ticket输出会重排。0.20.74会因此误报状态变化，首次检查未通过。

0.20.75只在`pcb.checkSilkscreen`内比较这些已证表示差异。对象键顺序不影响比较，数组顺序必须保持。唯一非墓碑PAD_NET按完整身份匹配，允许有效数值ticket重编；其余header和全部data必须一致。非PAD_NET的相对行序、ticket和data仍须保持。DOCHEAD仅忽略client/updateTime/version。

重复身份、墓碑、增删记录、实际网络或几何变化、未知DOCHEAD变化和独立设计规则变化都会作废结果。共享GeometryHost和写入指令的检查不变，不自动重发导出。

成功回执的`sourceComparison`分别说明开始、结束时接受的表示变化；`sourceStable:true`表示设计数据在上述规则下保持，不代表源码字节完全相同。`rulesStable:true`独立确认前后设计规则保持。

### 0.20.75 安装版限定验收

EDA4.1.78 独立 B123 工程已通过近焊盘、移远、换面、板边间距及板外文字对照。5 mil 板边要求下，实际制造丝印距名义板框约 3.79 mil，检查正确报告不足。近焊盘的实际丝印位于同面阻焊开口内，移远或换到底面后不再报告。独立读取 Gerber 的核对结果一致。

保存、关闭重开后，新增文字的位置、面和属性保持。原有 193 条设计记录 data 保持。源码表示重排不再误报；独立设计规则检查保持。最终安全位置不报告制造冲突。

结论只覆盖当前支持的制造图层和上述测试场景。原始图元可能被导出裁切；合并后的制造丝印不能还原每个对象的身份，也不能完整检查丝印对象互撞。此测试页单次检查约 33–71 秒，不能据此保证其他工程的耗时。

## 制造参数与订单核对（0.20.77候选，安装版待验）

用一份带来源的JSON制造参数文件记录实际选择的叠层、官方计算输入和输出，再调用`pcb.checkManufacturingProfile`核对。命令接收`profile`对象内容，不接受本机文件路径。可另传`orderConfirmation`实际订单确认记录。参数以当前窗口help为准。

先选定具体叠层名称，再使用其计算结果。不能仅凭相同板厚和铜重混用不同叠层的线宽。名义板厚与叠层成品厚度分开记录。计算线宽与当前网络规则的首选线宽、min/max分别比较；落在范围内不代表首选相同。

没有网络/层映射时不猜目标。订单缺失、计算证据未确认或物理单位/层序未知时，总结果不能通过。`verified`只表示调用方提供的计算证据声明，插件不独立认证计算器，也不在线读取订单。不检查已有走线、参考平面连续性或实测阻抗。

### 来源地址结构校验（0.20.77候选）

0.20.76安装实测在来源参数校验时误拒绝合法网址，未进入工程读取。原实现依赖`new URL`并把所有异常误归为输入无效。本地移除该构造器后可复现；这不是已直接测得宿主全局对象的结论。

0.20.77对profile、计算记录及订单记录的来源统一进行本地绝对地址结构校验。HTTP(S)检查主机、authority和端口；file/mailto/urn等绝对scheme继续支持。中文路径与结构合法的国际化主机保留原值。拒绝相对地址、控制字符、原始空白、破损百分号及畸形authority。

此检查不依赖浏览器URL构造器，不联网，不修改地址，不做完整WHATWG/IDNA解析或规范化。地址结构通过不表示来源真实，也不把unverified改为verified。首次修复候选仍需安装版验收，不把本地回归代替宿主结果。

### 指定路径差分走线（0.20.79候选，安装版待验）

`pcb.routeDiffPair` 按中心路径生成正负两条耦合折线。调用前查询当前窗口help。`pair` 明确提供 `{positiveNet,negativeNet}`，两个网络必须存在且不同。`path`、`width`、`gap` 使用mil。gap是铜边距离，中心线距离为width+gap。

正侧按路径前进方向的数值法向 `[-dy,dx]` 偏移，负侧反向。屏幕视觉左右取决于坐标方向。反转path会交换两根线所在的空间侧，不会交换输入网名。

先用 `dryRun:true` 读取并预览；省略或false时执行写入。指定层须为已启用SIGNAL层。只删除几何等价的连续重复点和同向共线中间点，不吸附或拉长输入。生成段沿用最短1mil；反转、自接触、正负任意段间距不足或数值不可靠时，整对写前拒绝。

两侧共用文档与时间预算。逐段读回，并核对最终源码覆盖、非LINE记录和规则保持。中途失败返回partial及已完成侧和失败候选证据，停止后续步骤；超时不取消宿主操作，不重发、不自动删除或回滚。后续独立命令不受持续锁定。

`plannedLengths` 只表示本次计划路径，不是整网实测长度。转角造成的两线长度差会明确返回。该命令不自动避障、蛇形调长、并联重复焊盘或建立差分规则，也不自动保存。成功后仍按项目要求核对实际连通、全板DRC、参考面和长度差；不从创建成功推断阻抗合格。

```json
{"cmd":"pcb.routeDiffPair","params":{"pair":{"positiveNet":"USB_DP","negativeNet":"USB_DM"},"path":[[100,100],[300,100],[500,300]],"width":6,"gap":4,"layer":"top","dryRun":true}}
```

示例数值仅演示参数，不是USB设计参数。生产线宽/线隙应使用同一份有来源的叠层和计算记录，与规则及实际订单核对。差分等长容差按具体接口要求确定，不默认套用10mil。

### 蛇形补长（0.20.80候选，安装版待验）

`pcb.tuneLength` 在指定区域给开放走线链补长。`net`、`targetLength`、`region:{xMin,yMin,xMax,yMax}` 使用当前PCB的网络和mil坐标。`targetLength` 是所选链的中心线总长，不是整网所有支线的长度之和。

用 `primitiveIds` 明确选择同网、同层、同宽且未锁定的开放单链。省略时，net与region须完整包含唯一候选直线。`tunePrimitiveId` 可指定其中一个调节段。指令只替换该段，其他选中段保持。region限制新增铜轮廓，调节段两端须完整位于区域内。

先用 `dryRun:true` 查看计划。省略或false执行写入。`side` 为auto、left或right，方向相对按端点坐标排序后的路径，正法向为[-dy,dx]。auto会试两侧和可用调节段。找不到当前蛇形族时返回原因，不代表所有布线形状都无解。

按D12优先使用可确认适用的项目规则。当前SDK没有可靠的局部蛇形容差、自间距读取接口，因此必须明确填写 `lengthTolerance` 和 `minSelfGap`。前者是累计总长误差，后者是涉及新增蛇形的非相邻线段铜边间距，不重新要求两段未修改旧线达到此值。不得用差分gap、差分默认10mil或网络相对长度容差代替。几何读回容差0.001mil与累计总长容差分别使用。返回parameterSources说明显式参数与当前未确认适用的规则映射，不声称已从工程自动取得数值。

目标已经在总长容差内时返回changed:false，不写入。目标更短且超出容差时明确报错。生成线段沿用最短1mil要求。原线中途接有支线、焊盘或过孔时，必须确认连接会保留；不能确认则写前说明对象及原因。特殊外形、跨层范围或覆铜实际接触不明时不猜测。

执行时先创建新局部路径并读回，确认原线和非目标记录保持，再删除明确的原调节段，最后核对枚举、源码及实际总长。失败可能返回partial、新线ID、删除尝试和旧旁路状态；unknown表示无法确认。此时停止依赖该结果，不自动重试、回滚或保存，后续独立命令不受持续锁定。

返回的计划长度和实际长度仅针对本次选中链。实际最小间距如实报告，不夹到请求值。成功不代表全板间距、连接、阻抗或制造通过；仍需按具体接口及实际叠层核对。Type-C重复脚分支与自动布线流程另行开发。

参数示意：选中一条200mil测试直线，目标220mil，明确提供lengthTolerance与minSelfGap，再dryRun预览。示例长度和容差由测试目的选择，不能当作USB、DDR或其他接口的默认设计参数。
