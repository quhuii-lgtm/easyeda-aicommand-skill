# 原理图 3 · 接线与逐区检查

按[连接与环境](setup.md)确认窗口、工程和图页。具体参数、默认值和回包查目标窗口的 `__help`。

## 直连与标签

- `schematic.linkWire` 仅在同向朝上或水平方向引脚且未指定 `jogDir` 时默认让 U 形路径向外绕行；显式方向仍按请求执行。该规则不覆盖任意符号本体碰撞，布线后仍检查图面。

- 同一功能区内，相近同网引脚在满足下列长度和避让要求时必须就近直连，包括 GND；不能用逐脚标签代替。
- 跨区、跨页和长距离连接按需使用标签或端口。
- 连接点使用软件认可的连接方式。
- 不相连的交叉要清楚，异网不要重叠共线。
- 默认直连路径不超过 40 格。
- 若当前接口无法读取网格步长，明确标注网格未知；不能声称已读取，也不能把 50 mil 当作实测值或固定要求。
- 网格未知时仅按保守坐标估算，画后读回端点并在 EDA 界面核对吸附结果。
- 路径长度累计经过的所有折线段，不能逐段套用 40 格。
- 有分支时，在所有端点对的最短连线路径中取最长值。
- 端点包括引脚、标签短线端和分支端。
- 不把所有支路长度相加当作一条路径。
- 超过 40 格先调整布局。不需要局部直连时可用同名网络标签。必须直连时按下文登记批准的例外。
- 40 格以内也要避开其他网络、符号和文字。
- 网络标签放在明确的短线端点，不直接贴在引脚上。
- 网络标签通常保持 `rotation: 0`；`rotation: 180` 会把文字倒转，不能用作文字向左对齐。
- 向左引出的短桩要留出足够文字宽度，并按标签锚点和实际显示检查可读性。
- 放置后核对标签实际连接的导线及网名。
- 相近 GND 直连后，每组通常保留一个标签。
- 不留多余的悬空尾线。

## 引线和留白

- 按符号实际朝向，先从真实引脚端点向符号外引线，再转弯。
- 目标在符号另一侧时，从符号外绕行。
- 不反向穿过符号本体、其他引脚或 NC 标记。
- 不固定某个针号必须向左或向右出线。
- 器件间距和汇流线位置先安排好，再画线。
- 避免接口、电容和支路之间留下无用的大空白。
- 器件、标签和文字必须放在所属功能框内，标题与内容之间留出空间。
- 缩短导线不能牺牲文字间距和图面清楚程度。
- 为避让增加必要折弯是允许的。

## 标签和 NC

- 专业版网络标签设置的是导线名称属性。
- 拖动标签前检查当前拖动设置。
- 拖动后检查原导线的名称是否改变。
- NC 表示已确认允许悬空的引脚。
- 未使用的功能脚仍须按手册处理。
- 不用 NC 掩盖原因不明的悬空问题。
- 专业版 NC 是引脚属性，标识应放在引脚端点。
- 接入原 NC 脚前清除该属性。

## 烧录焊盘、测试点和 0Ω 连接

- 按选定烧录方式画出所需信号、参考地和目标电压连接。
- 所需复位和启动配置连接不得遗漏。
- 多颗可编程器件分别核对烧录路径。
- 检查其他器件是否占用或干扰烧录引脚。
- 检查烧录器与板上电源是否会互相反灌。
- 测试焊盘使用明确的位号、网络和封装。
- 测试点标明用途，必要时标明正常电压或信号范围。
- 明确测试时使用的参考地，不把隔离两侧的地混接。
- 0Ω 电阻按真实器件绘制，标明两端网络和用途。
- 需要拆开测量时，检查其他路径是否仍把两端连通。
- 写清 0Ω 电阻的默认装配状态和测试后的恢复要求。
- 裸测试焊盘需要转 PCB，但不应成为待采购或贴装的器件。
- 0Ω 电阻或实际安装的测试端子按装配要求进入 BOM。

## 接线命令的使用条件

`schematic.linkWire` 不设置网名。需明确命名的直连，按当前帮助用带网络名的 `drawWire` 或在已有导线上设置名称并读回；不能把电气已连通等同于具备预期网名。

- `schematic.labelWire` 将实际引脚接入命名网络。引脚已接异名网络时先查原连接。标签必须实际附着，结果未知时停止依赖写入。

- `schematic.linkWire` 直接连接两个实际引脚。自动路径可能穿过符号，需核对图面、网表和 DRC。

- `schematic.batchWire` 批量接线。检查逐项结果和网表审计；遇到结果未知的写入时停止依赖项。

- `schematic.drawWire` 用 `points` 指定路径，并可设网络名、颜色、线宽、线型和标签位置；具体字段按窗口帮助。创建后核对完整线段、网络和非目标对象。宿主合并、属性变化或读回延迟可能导致 `partial`；先读回现场，不盲目重发。异网导线交叉、重叠或端点相接不能当作安全连接。NC 引脚不得接线。源码 Y 坐标与公开 API 坐标方向相反，不能直接传入绘图指令。

- 内部 T 接只在已支持的特定线型和接入方向上有窄适配；核对原线完整拆分、请求支线、网络、样式和非目标对象。不能推广到反向接入或多条 WIRE 合并，也不能仅凭审计通过认定图面无遮挡。

- `schematic.placeNetLabel` 放置标签时锚点必须落在线上；文字靠近导线不代表连接。`listWires.line` 是宿主原始扁平编码，多段线可能由每四个数描述一段，需结合有效源码 LINE 核对，不能直接当连续折线顶点。器件旋转或镜像后重新读 `listPins` 获取实际引脚端点。

- `schematic.modifyWire` 修改时先核对目标线和源码，保留未请求变更的颜色、线宽、线型及 NET 状态。区分无 NET 属性、空 NET 和非空 NET；仅为已有空 NET 明确传 `net:''`，不为无属性导线补网名。线型值以窗口帮助和读回为准。每根线及批次结束后核对对象、NET 属性、LINE ID、端点和样式；失败或恢复结果未确认时停止依赖写入。

- `schematic.modifyNetLabel`、`setWireNet`、`repairNet`、`dedupeWireNets` 等按目标帮助使用。修改后核对标签附着、导线网络及原样式；重复属性计数不为零表示尚有重复项。`dedupeWireNets` 对不支持的几何或混合样式会拒绝，不能丢段后继续。

### 连线异常怎么处理

| 现象 | 先读什么 | 何时继续 |
| --- | --- | --- |
| `drawWire` 回报 `partial` 或超时 | 查任务状态，按原生 `LINE` 核对实落线段，并查看异常涉及的属性及非目标对象。 | 结果明确后，只补确认缺失的线段。已落线段保留。原因不明或属性仍变化时停写。 |
| `labelWire` 报失败或标签回包缺失 | 查导线、标签 ID、父导线和实际附着。 | 线和标签齐全时保留。确认无残留后，可改用明确坐标画短线再加标签。 |
| 结构审计报同网重叠或异网桥接 | 按原生 `LINE` 的每段端点复核，再查网表与局部图。 | 保留原审计结果。只有原生几何及实际网络支持时才把提示记录为误报。 |

只读结果出现暂态匿名网时，先让宿主拓扑刷新，再读取一次网表。持续不一致时保留两次结果并定位差异。

## 逐区检查后再完成

逐区复查摆放阶段记录的目标。用实际器件锚点检查同列或同行，用引脚和线段读回检查直线、路径长度及区框尺寸。长度目标和 40 格要求分别核对。脚本报告缺少坐标或路径时补读回；文字留白和遮挡用最新局部图确认。返工后对同一区重跑，并再次核对逐脚网络和 NC。

用 Node.js 运行 [check-schematic.mjs](../../scripts/check-schematic.mjs)，传入同一区的设计 JSON 和插件读回 JSON。设计可用 `alignments` 记录对齐组，区框用 `maxWidth` 或 `maxHeight`，两脚直连用 `requireStraight` 和 `maxLength`。对齐使用器件读回的 `anchor: [x, y]`。按当前区记录需要的目标和不适用的理由。

- 对指定的两脚直连组，脚本报告一条最短实际路径的长度和折弯数。连续同向线段按一段计。
- 画线前确定长度、直线和折弯目标。可用 `maxBends` 检查折弯上限。三折及以上会提示复核，结合引脚方向、避让和局部图判断是否能消除绕行。
- 默认上限为 40 格。全区 `maxDirectGrids` 可以设得更严，超过 40 会报失败，并继续按 40 格检查。
- 确需放宽时，写明充分的设计理由并取得用户确认，或记录通过的专家评审。例外只用于获批的引脚对。
- 将独立批准 JSON 作为脚本第三个参数。文件包含 `page` 和 `exceptions`。每项填两个准确引脚 `endpoints`、上限 `maxGrids`、原因 `reason`、批准人 `approvedBy` 和批准记录 `approvalRef`。脚本检查字段，执行者核对批准来源。
- 返工时可在设计的 `regions[].baselineBounds` 填原区框，报告面积变化。
- 检查块间空白时，在设计的 `regions[].blockGaps` 填两个子块名 `blocks`、测量轴 `axis` 和间距上限 `maxGap`。读回区的 `blockBounds` 按子块名提供实际边界。间距使用源码坐标单位。
- 接线后用局部图复查子块间和区框边缘的空白。收紧布局时为标签、标题和引线保留空间。

每区接线后读取 `listComponents`、`listPins`、`listWires` 和 `listNetLabels` 核对本区内容；用 `exportPng` 或当前界面查看局部，整页缩略图不代替放大检查。确认分区框、标题、短连线、标签和文字避让后，再继续下一区；接口连接随相邻区完成后统一核对。

`structuralAudit` 可筛查异网桥接、框重叠、出区和碰撞候选，但不保证检测漏画的分区或全部视觉问题。零项 DRC 或审计通过不能代替逐脚网表比较和图面检查。因工具缺失而不能检查时列明未完成项，不能自行跳过后报告全部完成。

### 可运行示例与结果判读

技能自带一套虚构 A4 示例。它包含区内直连和两页共网。输入为 [design.json](../../examples/schematic-audit/design.json) 和 [readback.json](../../examples/schematic-audit/readback.json)。在技能目录运行：

```sh
node scripts/check-schematic.mjs examples/schematic-audit/design.json examples/schematic-audit/readback.json
```

示例默认做整页复验。复制设计 JSON，把 `stage` 改为 `planning` 或 `wiring`，可分别试跑画前预检和逐区验收。示例只有一个功能区，三种模式可共用读回文件。
实际使用时，预期 JSON 取自已确认的电路或连接表。实际 JSON 取同一范围内的最新插件读回。用原生 `LINE` 的端点构建 `nodes`、`segments` 和 `wirePaths`，将源码 Y 转为接口坐标。网表用于核对逐脚网络，NC 以显式引脚属性或源码标记为准。

| 退出码 | 含义及处理 |
| --- | --- |
| 0 | 已提供的检查通过。 |
| 1 | 有检查失败。修正后重查受影响范围。 |
| 2 | 输入或运行出错。查看错误输出，修正输入或调用。 |
| 3 | 有候选或未完成项。缺读回就补读回，候选逐项复核，人工检查在验收记录中注明证据。 |

示例的 `planning` 返回 0，`wiring` 和 `sheet` 返回 3。脚本把图面交给执行者检查，整页还需独立核对 DRC、结构和保存重开。零失败的报告仍可能有未完成项。

## 命令索引

| 任务 | 命令 | 用途 |
| --- | --- | --- |
| 接线 | `schematic.labelWire`、`schematic.linkWire`、`schematic.batchWire`、`schematic.drawWire` | 单引脚接网、两脚直连、批量接线或指定路径绘线。 `linkWire` 必须恰好提供两个引脚。 |
| 网络标签 | `schematic.placeNetLabel` | 指定网络标签位置；`drawWire` 已设置网络名时不要再在同段线上叠加同名标签。 |
| 网络与标签修复 | `schematic.setWireNet`、`schematic.modifyWire`、`schematic.dedupeWireNets`、`schematic.repairNet`、`schematic.listNetLabels`、`schematic.pruneFloatingLabels`、`schematic.fixNetLabels`、`schematic.modifyNetLabel`、`schematic.moveLabel` | 核对或修复导线网络和标签；先读目标对象，写入结果不明时停止并核对图面及网表。 |
| 引脚与 NC | `schematic.connectPin`, `schematic.setPinNoConnect` | 接入实际引脚或设置 NC。 |
