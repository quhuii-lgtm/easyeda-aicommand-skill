# PCB 6 · 检查与保存

具体参数、默认值、回包和示例以目标窗口的 `__help` 为准。

## 修改前后比较

修改、删除及保存读回按[PCB操作流程](pcb-06-verify-and-save.md)执行。比较修改前后的网络与几何位置，并保留无法解释的差异。
- 同网走线合并后，核对端点、路径、所在层和线宽。
- 铺铜生成 ID 变化时，另核对边界、填充几何和连接。
- 仅生成 ID 变化与实际铜面变化分别报告。

## 完成检查

先写清PCB、图页/板号、本轮对象和验收阶段；局部任务只验目标及受影响接口。原理图连接表、板框机械条件、关键网络要求及制造工艺以已确认版本为准。

### 验收项目、方法和通过条件

| 项目 | 怎么验 | 通过条件 |
| --- | --- | --- |
| 设计对应与网络 | 用 `listComponents`、`getComponentPads`、`listNets` 和适用的网表/网络图元读回，对照器件、封装、针序及全部必连焊盘；重复通道逐实例核对。 | 无漏件、错封装、错极性或意外改网；空网焊盘已按用途确认，不为清告警强行补地。 |
| 板框、孔槽与机械 | 对照机械图及实际板框、孔槽、器件位置与外形，查看顶底面及适用的三维/装配资料，检查高度、插拔、固定和测试接触空间。 | 尺寸、位置和朝向满足已确认条件，无本体或装配干涉；仅焊盘不重叠不能判机械通过，缺少必要资料时注明未完成。 |
| 层叠和规则 | 读当前可用的图层、规则及物理叠层记录，对照信号层、参考面、铜厚、介质及网络/分层/区域规则；接口不支持时用适用资料或界面核对。 | 采用的设计条件明确，实际作用对象正确；铜层数或层名不能代替真实叠层，不以默认参数填补未知。 |
| 布局与可布线性 | 用真实焊盘、`checkPlacement` 及最新局部图检查功能组、关键配套器件和出口；受限共用通道按线组、线宽、间距、孔和全层障碍核对。 | 必要局部电路和返回路径位置合理，相关线组有可行空间；碰撞候选须复核，工具跳过或焊盘包围盒近似不算完整布局检查。 |
| 走线、过孔与连通 | 用 `listLines`、`listVias`、`getNetInfo`、`getNetPrimitives` 及适用DRC核对实际端点、网络、层、线宽、铜外径/钻孔和焊盘接触；放大关键接点。 | 本轮连接符合预期；整板布线验收无未处理的必连断路。飞线刷新、非空ID、分段数量或自动布线服务完成均不能代替连通检查。 |
| 关键电气路径 | 按项目及原厂要求逐段核对功率路径、取样、参考面、回流、换层、差分及长度；用实际几何和选定参数计算或核对。 | 必需的载流/压降/温升、阻抗/时序及返回条件满足依据；不适用项注明，工具不能覆盖的内容补查，缺数据不称通过。 |
| 覆铜与丝印 | 用 `listPours`、`getPourFillReadback`、`checkSilkscreen` 及最新顶底面图核对实际铜面、开窗、位号、极性、板边和针序。 | 需要的铜已填充且连接/连续性正确，丝印清楚可读；边框、no-fill、来源候选或complete:false不能代替已核实结果。 |
| DRC与制造 | 整板最终版运行 `runDrcDetailed` 并检查完整覆盖；制造交付按实际输入执行 `runDfm`、`runSmtDfm` 及 `checkManufacturingProfile`，核对制造文件和订单条件。 | 无未解决错误，其余告警按项目已确认的方式处理；工具不支持、跳过、近似和unknown逐项补查或列未完成，不改规则或默认工艺掩盖问题。 |
| 图面与保存 | 查看修改后的顶底面、关键局部及适用层图，核对对象和当前PCB；按下节保存/重开，比较目标与非目标内容。 | 图面及保存状态与本轮检查一致；旧截图、局部DRC或命令成功不能作为整板通过依据。 |

布局、布线、电气、机械和制造分别给结论。仅布局或局部修改时，尚未开展的整板布线/生产项目注明不在本轮范围，不得顺带报通过；制造交付缺少必要资料则列未完成。实时或自定义DRC不冒充完整检查，清标记不等于修复。

### 保存与重开范围

- 新绘整板、整板正式交付：写入结束且保存确认后，关闭并重开受影响PCB，核对身份、器件属性、焊盘网络、线路/过孔、规则、实际覆铜及最新图面与保存前一致。
- 普通局部调整，包括位置、角度、丝印、属性、增补线路或常规重铺铜：核对目标、受影响连接及非目标内容并保存，不因此要求每次重开整个工程。
- 本轮交付涉及删除/更换器件或既有路由、修改网络或层叠、复制PCB，或明确要求持久性检查时：保存后重开受影响PCB并检查相应内容，不只比较图元ID或数量。
- 未重开只报告“已保存，未验证重开”；实际读回核对后才报告“保存重开已验证”。写入或保存结果未知时先核实原操作，不强行关闭、重发或用保存掩盖问题。

### 验收结果怎么报

写明PCB、板号/版本、本轮对象及布局/布线/制造等阶段；上述项目分别列行，多功能组注明范围，不粘贴全部原始回包。

| 项目及范围 | 结论 | 检查依据 | 未解决或未完成项 |
| --- | --- | --- | --- |
| 功能组/网络/对象及验收项目 | 通过／不通过／未完成／不适用 | 当前对象读回、路径/规则比较、实际查看的图像或DFM文件结果。 | 具体问题、缺少的检查及原因；无则写无，不适用时说明。 |

保存项写明实际保存/重开状态。任一适用项不通过则整体不通过，必检项未完成不能报告整体通过；局部通过不扩大为整板、可生产或实物性能通过。参数或规则改动后，只重查受影响项目和依赖检查。

## DRC之后执行DFM

本节用于制造交付；布局或普通局部任务不要求顺带下单。整板完整DRC通过后，按本次拟下单工艺执行PCB DFM及适用的SMT制造装配检查。
从技能入口直接选读DFM命令说明，核对当前版本、参数与覆盖限制。

- 核对目标PCB、保存版本、板材、板厚、铜厚、层叠及装配工艺。
- 对照图纸、检查输入和拟下单工艺，记录差异与处理结果。
- 核对返回的完整性、逐项结果和覆盖范围，不能只看API成功。
- 工具跳过、不支持或近似处理的必要内容，用适用方法补查并保留依据。
- 不支持的工艺不能改填为工具支持的默认工艺来取得通过。
- 修复后重新检查，最终提交版本保留完整DRC与适用DFM结果。
- 需要厂商解析才能完成的检查，先导出检查文件并按已有授权上传。
- 解析通过前不提交订单。

返回报告版本、输入工艺、逐项结果、补查依据及未解决事项，供项目阶段验收使用。
工具覆盖范围内通过不能代替全部制造要求通过。

## 检查、保存和生产导出

按[PCB完成检查](pcb-06-verify-and-save.md#完成检查)统一执行验收表、保存重开范围及结果格式。布局、布线、机械、电气和制造分别判断；本节不是每次局部修改都必须完成制造检查的要求。

1. `pcb.runDrcDetailed` 用具体对象、网络、规则和图层定位问题，不只看总数。
2. `pcb.runDfm`、`pcb.runSmtDfm`、`pcb.checkManufacturingProfile` 按任务使用。参数档案需有来源，真实板厂叠层、计算和订单分别核对。
3. `pcb.save` 后按上述统一范围核对；整板正式交付及要求持久性验证的改动，关闭重开受影响PCB并比较关键内容和非目标对象。
4. 按任务导出Gerber、BOM、坐标或网表，并按[生产文件操作要求](manufacturing-file-requirements.md)核对单位、层、孔和器件信息。

DRC通过、制造图形检查和生产订单一致性是不同结论。具体设计未提供生产资料时，不由插件补猜板厚、铜厚、Dk或阻抗参数。

## 下单工艺检查与制造参数

### 嘉立创下单检查

`pcb.runDfm` 检查 PCB 工艺，`pcb.runSmtDfm` 检查 SMT 贴装，`pcb.checkSameNetPadSpacing` 单独检查同网焊盘间距。三个入口位于 PCB 页的「AI 指令引擎」菜单，与命令共用检查处理和结果汇总。检查不会自动修图、保存、上传或下单。

下单铜重由用户按本次订单明确提供。先确认目标窗口帮助支持所需字段。铜重只用于 PCB DFM。

PCB DFM 覆盖 18 项，SMT DFM 覆盖 7 项，同网间距命令覆盖 1 项。回包的 `data` 包含 `results`、`expectedCount`、`issues`、`coverage`、`documentUuid`、`checkType`、`inputs`、`timestamp`、`upstream` 及汇总状态。只有 `complete:true` 且 `passed:true` 才能报告该命令覆盖范围内通过。`ok:true` 只表示处理器返回成功；`upstreamPassed` 是兼容字段，不代表嘉立创在线服务已通过。

输入不全、读取失败或必要数据使用回退/推断值时，检查必须是不完整。应同时检查 `coverage`、`issues` 和 `upstream`，不能只看 `passed` 或问题数量。源铜厚报告与 DFM 判定分开；图纸铜厚不一致、物理层记录缺失或无法解析，不自动构成 DFM 失败，也不能据此判断铜重命中。

这些命令复用本地工艺参数表与几何算法，不是嘉立创网站实时同步的全量检查，也不是生产放行。现有几何近似包括：线间距只计算 `Line` 正间隙，不覆盖接触、重叠、`Arc` 或 `Polyline`；长圆及不等边焊环按最大轴近似；同网焊盘间距按胶囊体和内接圆近似。有效铜层数量使用铜图元启发式，器件类别可能按名称识别，定位 ID 可能由列表索引辅助匹配。报告中的位置仅用于辅助查看，命令不自动修复图纸。

菜单可显示逐项结果和问题位置，并由用户选择导出 TXT 或 JSON。AI 命令不弹保存窗口，也不清日志或自动写报告。定位前确认当前 PCB 与报告目标一致；不能把另一块板的坐标用于定位。

### 制造参数、订单和规则核对

`pcb.checkManufacturingProfile` 只读比较调用方提供的 JSON `profile` 与当前 PCB 可读规则，不保存参数、不改板、不下单。用文件内容传入 `profile`；不要把它写进工程描述，也不要声称扩展配置随工程保存。

准备板厂叠层、下单选项和真实订单确认。有阻抗要求时，提供实际计算记录及网络与 EDA 铜层的映射。按帮助填写制造参数。没有证据时保留未知，区分名义板厚与成品板厚。

逐项核对匹配、不匹配、未知和不适用。只报告证据覆盖范围内的匹配。物理层读数和顺序只作来源证据，不能确认实际制造叠层或订单。

官方资料：[嘉立创阻抗与叠层说明](https://jlcpcb.com/impedance)、[嘉立创阻抗计算器](https://jlcpcb.com/pcb-impedance-calculator)。配置选择器格式参考[官方规则选择器说明](https://github.com/easyeda/easyeda-format-skill/blob/main/primitives/PCB/rule_selector.md)。资料定义本身不证明当前宿主采用方式或生产合格。

## 网络与生产导出

| 命令 | 输出或用途 | 判读限制 |
| --- | --- | --- |
| `pcb.exportDsn` | 导出自动布线输入 DSN；在支持的版本中也返回与 DSN 对应的 `routeBaseline`。 | 保留原返回对象和实际送交服务的 DSN；不证明规则完整。 |
| `pcb.exportNetlist` | 导出当前 PCB 网络表。 | 导出成功不等于网络连接正确；对照目标板和网络来源。 |
| `pcb.exportGerber` | 导出制造 Gerber 数据，返回内容按当前帮助处理。 | 必须核对图层、孔、板框及文件完整性；导出成功不代表生产验收。 |
| `pcb.exportPickPlace` | 导出贴片坐标数据。 | 需核对器件、单位、坐标原点和方向；导出成功不代表贴装数据已验收。 |
| `pcb.autoRouteGetResult` | 取回服务原始 SES 文件名和 Base64。 | 只读，不等于已导入或已保存。 |

生产导出由调用方按返回格式解码或保存；核实当前帮助中的编码、内容和文件字段。逐项检查导出完整性以及工程与目标制造设置是否一致。文件存在、Base64 可解码或布线服务成功都不能替代文件内容检查、PCB DRC、制造审核或实际订单确认。

## EDA 版本限制

EDA 4.1.78 对以下入口有明确的版本保护：`pcb.getCurrentLayer`、`pcb.listStackingConfigs`、`pcb.getStackingConfig`、`pcb.applyStackingConfig`、`pcb.saveStackingConfig`、`pcb.renameStackingConfig`、`pcb.deleteStackingConfig`、`pcb.setDefaultStackingConfig`、`pcb.startRealTimeDrc`、`pcb.stopRealTimeDrc`、`pcb.getRealTimeDrcStatus`。当前宿主会报告需要 EDA 4.2；实际执行、保存和读回仍需在支持版本核验。


需要生产交付时，继续按[生产文件操作要求](manufacturing-file-requirements.md)核对输出和订单。
