# 原理图 2 · 器件放置与布局

按[连接与环境](setup.md)确认窗口、工程和图页。具体参数、默认值和回包查目标窗口的 `__help`。

## 器件和封装

- 检查脚号、脚名、电气类型和隐藏引脚。
- 多单元符号要对应同一物理器件。
- 转 PCB 的器件，每个符号脚都要匹配封装焊盘。
- 封装可以有额外焊盘，其用途必须查清。
- 不强制符号脚数等于焊盘数。
- 网络标识等不转板符号按其用途检查。
- 核对型号、参数、料号和封装。
- 核对是否进入 BOM、是否转 PCB，以及是否装配。
- 3D 外形不能证明引脚映射正确。

## 器件和支路

- 按连接关系分组摆放。先读实际引脚，调整器件方向和位置，让适合直连的引脚相对、同轴。
- 同组器件可共行或共列时优先对齐。对齐导致绕线、穿符号或文字拥挤时，按实际引脚与留白调整。
- 接线前先把并联器件和反馈支路摆近，能对齐的先对齐。
- 按实际引脚出线方向选择器件朝向。
- 记录本区的对齐关系、应保持直线的引脚对、路径长度目标和区框尺寸目标。
- 返工或缩框后，读回器件锚点、引脚和区框，再看最新局部图。为标题、网名、位号、参数和 NC 留白。
- 电阻、电容按所接引脚的方向摆放，减少绕行。
- 输入或输出并联电容可竖放在芯片对应侧。
- 电容的电源端接短汇流线，地端就近合并。
- 上下汇流线都应靠近器件，同时留足文字空间。
- 摆放时检查实际脚位和极性，不为整齐增加长线。
- 两引脚之间放不下元件时，优先让正极或信号端直连。
- 这种情况下，负极或地端可用带短线的标签连接。
- 空间足够且路径合适时，两端都可就近直连。
- 端接电阻等支路放在所属接口侧，并核对每个脚的原网名。
- 不为两端都直连而绕远或穿过其他引脚。

## 去耦电容

- 去耦电容靠近对应电源脚，优先直接接到该电源脚和邻近地回路。
- 缩短电源脚、电容和地回流组成的高频回路，不只看电容与芯片的直线距离。
- 大小不同的去耦电容按电源网络并联，并核对每颗电容的电源端和地端。
- 避开电容、器件位号和网络标签文字，保证连接关系清楚可读。

## 放置、读回与调整

- `schematic.placeDevice` 放置单件，必需参数及坐标以窗口帮助为准。可用 `lcscId` 与 `libraryUuid` 限定库；省略库沿用 SDK 查询范围。返回的 `device` 标识实际器件和库；`placementVerified` 只表示实例读回，`footprintVerified`、`footprintStatus`、`pcbReady` 和 `pcbReadyScope` 分别说明封装及引脚/焊盘映射核对范围。无封装符号仍可能放置并带警告。创建后核验异常时先查现场，不重放。用 `schematic.getPlacementResourcesDiagnostic` 只读检查现有实例。

- `schematic.modifyComponent` 提交完整属性对象；先读出现有工程属性并保留 `otherProperty` 自定义键，不用库器件默认值覆盖工程实例。

- `schematic.setAttribute` 按窗口帮助修改已有属性。目标或参数查找失败属于写入前拒绝；调用开始后的异常、等待或读回未确认应按 `partial:true`、`retryable:false` 处理。先查属性和原调用状态，不直接重放。

- `schematic.moveComponent` 不会移动旧导线。`schematic.autoLayout` 只用于整理已有功能区；先限定目标并运行 `dryRun`，真实运行前保存。`rewire` 会删除并重建相关线；检查跳过线和部分移动。失败时核对 `error.cause.moved` 与现场，不假定回滚。

## 命令索引

| 任务 | 命令 | 用途 |
| --- | --- | --- |
| 放置器件 | `schematic.placeDevice` | 放置器件后核对封装资源和引脚映射；放置成功不代表可直接转入 PCB。 |
| 修改 | `schematic.moveComponent`、`schematic.modifyComponent`、`schematic.setAttribute` | 移动器件、修改器件或属性。 |
| 资源诊断与布局 | `schematic.getPlacementResourcesDiagnostic`, `schematic.autoLayout`, `schematic.getAttributes` | 检查资源、预览布局、读属性。 |
