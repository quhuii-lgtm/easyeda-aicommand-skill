# Schematic Operation Requirements

This page covers drawing, editing, and result checks. The project supplies the confirmed scope, intended connections, and design conditions.

Manage stage acceptance and project records according to the project plan. For online work, use the command pages linked from the skill entry and help for the installed version. For offline generation or another backend, apply only relevant drawing and design requirements; do not use them to initiate online writes.

## Plan Functional Areas and Pin Connections

- For a multi-area drawing, plan each area's position, reading order, and title space.
- Size area borders for actual symbols, pin leads, labels, and property text. Allow extra room for large modules and high-pin-count parts.
- Set component spacing from symbol dimensions; do not reuse fixed coordinates from another project.
- Before batch placement, prepare part numbers, intended designators, and a pin-to-net table. Reuse part research already obtained and prefer batch lookup when supported.
- Identify pins by component and pin number; distinguish units in multi-unit components.
- Check the `refMap` returned by `buildBlock`, then compare actual designators and pin wiring.
- List power, ground, signals, and valid NC pins separately. Confirm the purpose of unassigned pins.
- Prefer direct connections between nearby pins on the same net. When a label is needed, lead a short wire outward from the actual pin connection point.
- Set label spacing for the current units, text, and neighboring pins. Do not apply an upstream 10-unit offset as a fixed rule.
- After generation, check that components, labels, and text stay inside their functional areas; adjust the layout or enlarge an area if needed.

These requirements guide planning and readback; they do not mean `buildBlock` automatically avoids symbols based on their dimensions. Adjust existing drawings only within the authorized scope; do not rearrange the whole drawing just to add functional boxes.

Reference: [Official schematic placement and pin-routing skill](https://github.com/easyeda/easyeda-enhanced-schematic-skill/blob/main/SKILL.md), checked 2026-10-10. Only its layout and batch-preparation methods are used here.

Continue to use this plugin's commands and the existing save and acceptance workflow.

## Components and Footprints

- Check pin numbers and names, electrical types, and hidden pins.
- Units in a multi-unit symbol must represent the same physical component.
- For components transferred to PCB, map every symbol pin to a footprint pad.
- Footprints may contain extra pads; determine their purpose.
- Symbol pin count does not have to equal pad count.
- Check non-board symbols, such as net identifiers, according to their purpose.
- Verify model, parameters, part number, and footprint.
- Check BOM inclusion, PCB transfer, and assembly status.
- A 3D model does not prove pin mapping is correct.

## Drawing Rules

Use these rules for new drawings and later cleanup. Direct-wire length and placement follow the user's stated defaults unless the project specifies otherwise. Distances on a schematic are not PCB electrical distances.

### Functional Areas and Net Names

- Arrange functional areas in reading order. Preserve the same functional relationships in repeated channels and check each one.
- Give each electrical net one clear name. Do not put different names or labels on the same wire.
- If different names are directly connected, verify the intended connection first. Use one name if they are the same net; if names must remain distinct, specify exactly where and how they connect.
- Do not use flexible multi-name net joining as the normal drawing method.
- For sheets and hierarchical sheets, check the correspondence between ports and nets. Local, port, and global names may differ only when their mapping is correct.

### Direct Wires and Labels

- `schematic.linkWire` defaults to an outward U-shaped route only for upward-facing or horizontal aligned pins when `jogDir` is omitted. An explicit direction is honored. This does not avoid arbitrary symbol-body collisions; inspect the drawing after routing.
- Within a functional area, prefer direct wires between nearby pins on the same net, including GND. Use labels or ports as needed between areas, pages, or for long connections.
- Use a connection method recognized by the software. Make unconnected crossings clear, and do not run different nets collinearly over one another.
- Keep a direct route within 40 grid cells by default. If the current interface cannot read the grid step, mark it unknown; do not claim to have read it or treat 50 mil as a measured or fixed step. When the grid is unknown, estimate conservatively, read endpoints back after drawing, and check snapping in the EDA interface.
- Count the entire polyline route, not each segment separately. For branches, find the shortest route between every endpoint pair and use the longest of those routes. Endpoints include pins, label-stub ends, and branch ends. Do not sum all branches as one path.
- Use a same-name net label for routes longer than 40 cells. Shorter routes must still avoid other nets, symbols, and text.
- Place labels at clear wire-stub endpoints, not directly on pins. Usually keep `rotation: 0`; `rotation: 180` flips the text and is not a way to left-align it. Leave enough text width for left-facing stubs and check readability from the label anchor and actual display.
- After placement, verify the attached wire and net name. Usually keep one label per group after directly joining nearby GND pins. Remove unnecessary dangling stubs.

### Components and Branches

- Orient resistors and capacitors to the pins they connect to, reducing detours. Input or output bypass capacitors may be placed vertically beside the corresponding IC side.
- Connect capacitor power ends to a short bus and join ground ends nearby. Keep upper and lower buses near the components while allowing room for text.
- Check actual pins and polarity; do not add long wires for visual symmetry.
- If a component cannot fit between two pins, prioritize a direct connection to the positive or signal pin. A negative or ground pin may use a label with a short wire. If space and routing allow, connect both ends directly nearby.
- Put termination resistors and similar branches by their interface and verify each pin's original net. Do not detour or cross other pins just to connect both ends directly.

### Decoupling Capacitors

- Place each decoupling capacitor near its corresponding power pin and connect it directly to that pin and a nearby ground return when possible.
- Minimize the high-frequency loop formed by power pin, capacitor, and ground return; straight-line distance to the IC is not enough.
- Parallel different decoupling values on the supply net and verify the power and ground side of every capacitor.
- Keep capacitor, designator, and net-label text clear so the connections remain readable.

### Leads and Spacing

- Follow the actual symbol orientation: lead outward from the real pin endpoint before turning. If the destination is on the other side of the symbol, route around the symbol body.
- Do not route backward through the symbol body, another pin, or an NC mark. Do not require a specific pin number to exit left or right.
- Plan component spacing and bus location before drawing. Avoid useless large gaps between interfaces, capacitors, and branches.
- Keep components and text inside their functional area when boxes are used. Do not sacrifice text clearance or readability just to shorten wires. Necessary bends for clearance are acceptable.

## Labels and NC

- In Professional Edition, a net label sets the wire's name property.
- Check the current drag setting before moving a label. After moving it, check whether the original wire name changed.
- NC means the pin is confirmed to be allowed to float. A function pin that is unused must still follow its datasheet; do not use NC to hide an unexplained floating pin.
- In Professional Edition, NC is a pin property and its mark belongs at the pin endpoint. Clear that property before connecting an NC pin.

## Programming Pads, Test Points, and 0-Ohm Links

- Draw the signals, reference ground, and target voltage needed for the selected programming method. Include required reset and boot configuration connections, and check the programming path for each programmable device.
- Check whether other components use or interfere with programming pins and whether the programmer and board supply could back-feed each other.
- Give test pads clear designators, nets, and footprints. Identify their purpose and, when useful, normal voltage or signal range.
- Specify the reference ground for testing; do not join grounds across isolated domains.
- Draw 0-ohm resistors as real parts and identify both nets and their purpose. If the link must be opened for measurement, check for alternate paths between its ends.
- State the default assembly state and restoration requirements for each 0-ohm resistor.
- Bare test pads transfer to PCB but should not become purchased or assembled parts. Include 0-ohm resistors and installed test terminals in the BOM as required by assembly.

## Edits and Batch Operations

Use the [schematic command workflow](commands-schematic.md) for edits, deletion, recovery, save, and readback.

- After moving, rotating, or mirroring a component, read its pin endpoints again. After rotation, plan wires from actual pin coordinates and directions returned by `schematic.listPins`; do not infer orientation from the designator or angle.
- A layout-only edit must preserve electrical connections and component parameters.
- Before modifying a shared wire, identify all branches and external endpoints.
- When replacing a component, recheck its full set of properties and assembly status.
- In Professional Edition, changing a value may clear the supplier number; recheck the part number afterward.
- The number of wire segments does not prove net connectivity.

## Reusing Modules

- Record source revision, operating conditions, and completed checks. Mark incomplete modules and undecided interfaces; do not treat them as production-ready.
- Check logic levels, direction, power domains, and unpowered states; also check pin order, polarity, footprint, surrounding components, and current return.
- For hierarchical modules, check the ports connecting them to the main sheet.
- Validate one unit first, then check each designator and channel net. Recheck pins and geometry for rotated or mirrored instances.
- A successful schematic reuse check does not mean the PCB can be copied directly. Recheck affected instances after changing the source module.

## Compare Before and After

Use the [schematic command workflow](commands-schematic.md) to compare component properties, nets, and positions. A layout-only edit must preserve connections and parameters; each electrical change must map to a requirement. Mark unexplained differences as pending verification.

## Schematic Completion Checks

- Check each programming connection, required test point, and removable 0-ohm link. Record when an existing interface is reused or a check does not apply.
- Compare every pin against the agreed connection table. Check required and prohibited connections, NC, polarity, and connector pin order.
- Check electrical types, floating pins, duplicate designators, required properties, multi-unit components, net names, and footprint associations.
- Run ERC and DRC. Confirm which pages, components, and rules are covered; explain exclusions. Do not hide issues by removing BOM or PCB inclusion. For each warning, record its fix, reason for acceptance, or unresolved status. Rerun affected checks after changing rules.
- Inspect each functional area enlarged, including components and every branch. Check each pin's lead direction, connection point, symbol/NC clearance, and text clearance.
- Confirm the displayed image reflects the latest edit, not a cached frame. A full-page thumbnail does not replace close inspection. After netlist and DRC pass, still check wires through symbols and text overlap.
- Finally check page grouping and reading order. Confirm the checked design is the saved current version.

## Transfer to PCB

- Verify project, board, schematic, target PCB, and assembly revision. In Professional Edition, schematic and PCB synchronization must target the same board.
- Save before synchronization and inspect the selected items in the change list. If rules must transfer, check “Include Design Rules” and its specific options.
- Apply the changes, then inspect the result. Verify each component, designator, footprint, pad net, and pin order.
- Do not combine production lists from different boards or assembly revisions.
- If nets change on a routed PCB, inspect old tracks, vias, branches, and copper zones. Repour as needed and recheck. Successful synchronization does not prove old copper still matches the new nets.
