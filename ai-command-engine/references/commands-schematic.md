# Schematic Commands

Before the first schematic write, read [schematic operating requirements](原理图操作要求.md) and this workflow in full. Confirm the target window, project, and active page using [connection and setup](setup.md). Use `/help?cmd=<command>` in that window for parameters and returns; `/help` is not routed by the request `instanceId`. First read the page, components, and actual pins using `schematic.getPageInfo`, `listComponents`, and `listPins`.

## Required order

Follow this order for a new drawing or the scope of the current edit: read the target and list areas/components/pin nets/allowed NC → draw each new functional-area box and title → place components, then read actual designators, pin endpoints, and orientations → arrange parts, branches, and text → connect one area at a time → inspect each area → compare the connection table, run ERC/DRC, inspect the page, and save. Reuse correct existing content and stay within the authorized scope.

Each new functional area needs a real box and readable title. A planned name or a box ID alone does not prove that the box and title were drawn correctly. After each area, read back components, pins, wires, and labels, then inspect its latest enlarged image before continuing. Nearby same-net pins in an area must be directly connected when appropriate, including GND; do not substitute one label per pin for convenience.

Use the unified [Schematic Completion Checks](原理图操作要求.md#schematic-completion-checks), including its seven acceptance items, pass conditions, save/reopen scope, and four-column result format. Do not omit items or create different pass criteria. Report visual layout and electrical connectivity separately.

## Functional areas first

For a new area, use `schematic.placeRegion` to draw its box and title, or reuse a box already created by `buildBlock`; do not draw a duplicate. Use `listRects` to check its `span`, and verify the title and actual image. Returning a box ID alone does not confirm the title was created.

`placeRegion` uses `x,y` for the upper-left corner and top edge of the box. `buildBlock.region` uses `x,y` for the lower-left corner. Both calculate with +Y upward, so do not reuse the same Y value without conversion. Adjust dimensions for actual components, pin leads, and text.

`buildBlock` is an initial placement and wiring macro; it does not guarantee the required layout or direct connections. Default power and multi-pin nets use a label on each pin. Explicit `style:"wire"` also connects directly only when the input resolves to exactly two pins. To directly connect nearby pins within an area, use `nets:[]` to create only the box and initial component placement, read back `refMap` and actual pins, arrange components, then wire one area at a time. An unwired area is not complete.

`schematic.linkWire` does not assign a net name. For a direct wire that needs an explicit name, use `drawWire` with a net name as supported by current help, or set the name on an existing wire and read it back. Electrical continuity alone does not prove the intended net name.

## Place and connect

- `schematic.placeDevice` places one component. Check required fields and coordinates in current help. `lcscId` and `libraryUuid` can constrain the library; omitting the library uses the SDK search scope. The returned `device` identifies the actual device and library. `placementVerified` confirms instance readback only; `footprintVerified`, `footprintStatus`, `pcbReady`, and `pcbReadyScope` describe the checked footprint and pin/pad mapping scope. A symbol without a footprint may still be placed with a warning. If creation or readback is abnormal, inspect the current project; do not replay the placement. Use `schematic.getPlacementResourcesDiagnostic` for read-only checks of existing instances.
- `schematic.labelWire` connects one pin to a named net. `pin` uses the actual designator and pin number, such as `U1.7`; `net` is required. `stubLen` is in schematic units, default 60 and minimum 20. `color` is optional; `force:true` permits merging a pin already assigned to another net. If a different net is already present, inspect existing wires instead of forcing. Check the returned stub, label ID, and attachment state. `alreadyConnected:true` means no duplicate wire was drawn. If the label is unattached, preserve the current drawing and stop dependent writes.
- `schematic.linkWire` directly connects exactly two pins in `pins` and does not assign a net name. Optional fields include `color`, `jogDir` (`down`/`up`; `left`/`right` are also supported for aligned offsets), and `force`. The default path is automatically orthogonal. Check returned `route`, segment count, and wire IDs. `alreadyConnected:true` means both ends already share a net. Check drawing, netlist, and DRC; an automatic path is not guaranteed to avoid all symbols.
- `schematic.batchWire` accepts `items` of type `label` or `link` with the parameters above. `continueOnError` defaults to `true`; `skipAudit` defaults to `false`. The response includes item results and netlist audit; it does not repair failures. An unknown write must stop dependent items even when continue-on-error is enabled.
- `schematic.drawWire` takes `points` and may set net name, color, width, line style, and label location; use current help for exact fields. After drawing, check all segments, net, and non-target objects. Host merges, property changes, or delayed readback can result in `partial`; inspect current state instead of retrying. Crossings, overlaps, or touching endpoints between different nets are not safe connections. Do not wire NC pins. Source Y coordinates are opposite the public API direction and cannot be passed directly.
- Internal T-junction adaptation applies only to supported line styles and connection directions. Check the original line split, requested branch, net, style, and non-target objects. Do not generalize it to reverse entry or merging multiple wires; an audit alone does not prove the drawing is unobstructed.
- For `schematic.placeNetLabel`, the anchor must lie on a wire; nearby text is not a connection. `rotation` is the text angle and defaults to 0. `listWires.line` is a flattened host encoding; every four values may describe one segment of a multi-segment wire. Confirm against valid source `LINE` data instead of treating it as one continuous polyline. After component rotation or mirroring, read actual pin endpoints again with `listPins`.

## Modify and delete

- `schematic.modifyComponent` submits a complete properties object. Read existing project properties first and preserve custom `otherProperty` keys; do not overwrite project instances with library defaults.
- `schematic.setAttribute` changes an existing attribute using current help. A target or parameter lookup failure is rejected before writing. Exceptions after invocation, waits, or unconfirmed readback must be treated as `partial:true`, `retryable:false`. Check the attribute and call state; do not replay directly.
- Before `schematic.modifyWire`, verify target wire and source. Preserve unrequested color, width, style, and NET state. Distinguish no NET property, empty NET, and non-empty NET. Pass `net:''` only to explicitly change an existing empty NET; do not add a net name to a wire that had no NET property. Use current help and readback for line-style values. After each wire and batch, check object, NET, LINE ID, endpoints, and style. Stop dependent writes if failure or recovery is unconfirmed.
- Use `schematic.modifyNetLabel`, `setWireNet`, `repairNet`, `dedupeWireNets`, and similar commands according to current help. Check label attachment, wire net, and original style after changes. A non-zero duplicate-property count means duplicates remain. `dedupeWireNets` rejects unsupported geometry or mixed styles; do not continue after a segment is dropped.
- `schematic.moveComponent` does not move existing wires. Use `schematic.autoLayout` only to arrange an existing functional area: constrain the target, run `dryRun`, and save before execution. `rewire` deletes and recreates related wires; inspect skipped wires and partial moves. On failure, check `error.cause.moved` and current state; do not assume rollback.
- Before `schematic.delete`, verify target ID and dependencies, then rescan. Use `task.get` for long tasks; timeout does not mean cancellation. If any write outcome is unknown, stop dependent writes. To confirm persistence, save, close, reopen, then check identity, properties, nets, and non-target content.
- Delete TEXT through the supported delete API and check source and model. Immediate deletion may be undone after save/reopen on the current host; `directDeleted` does not confirm persistent deletion. If the result is unknown or readback is incomplete, stop. Do not switch to whole-page source writeback, retry, or compensate. Help documents this persistence limit; it does not disable every delete path.

## Check each area before completion

Follow the unified [Schematic Completion Checks](原理图操作要求.md#schematic-completion-checks), including the seven acceptance items, save/reopen scope, and result table. After wiring each area, read `listComponents`, `listPins`, `listWires`, and `listNetLabels`; use `exportPng` or the current interface to inspect an enlarged view. A full-page thumbnail does not replace close inspection. Confirm its box, title, short connections, labels, and text clearances before moving on. Check interface connections with the adjacent area.

`structuralAudit` can screen for cross-net bridges, overlapping boxes, out-of-area objects, and collision candidates. It cannot confirm that no functional area was omitted or that all visual issues are acceptable. Zero DRC findings or a passing audit does not replace pin-by-pin netlist comparison and drawing inspection. List unavailable checks as incomplete instead of skipping them and reporting full completion.

## Checks, netlists, and export

- `schematic.listNets`, `listWires`, `getNetlist`, and `exportNetlist` help inspect nets and pins. Confirm intended connections from the netlist and run DRC. `listComponents.allPages` and `structuralAudit.allPages` are Boolean. `structuralAudit.ncExempt` is an array of strings. `deviceMargin` defaults to 10 mil and otherwise must be finite and non-negative. `exportPng` width and height are integers from 1 to 4096; omitted values use defaults.
- If closing DRC results from `schematic.runDrc`, `schematic.runDrcDetailed`, or `schematic.buildBlock` are not arrays or have unknown structure, the result is indeterminate, not a pass. `schematic.buildBlock` generates a complete functional block but does not replace component-by-component and connection checks.
- EDA 4.1 `listNets` may use a PADS netlist and named wires to list automatic net names, but `detail:true` does not guarantee that unnamed wires are assigned to automatic nets. Use `getNetlist` to inspect pins. Point and region primitive queries require EDA 4.2 or later.
- `getNetlist` defaults its `netlistType` parameter to `Protel2`. `JLCEDA` uses the official file-generation path and returns raw text; `length` is string length, not bytes. File generation may update designators, Unique IDs, or save the project, so it is not read-only. If the JLCEDA path fails, do not fall back or resend. Unknown results return `partial:true`, `retryable:false`; dependent macro steps stop. Timeout does not mean the underlying operation was cancelled. Other netlist types use the SDK string path. Parse and check any non-empty netlist.
- `exportNetlist` may also update designators, Unique IDs, or save the project. `exportBom` defaults to `fileType=csv` and preserves host file bytes. Decode using returned `format`, `encoding`, and `delimiter`. Filenames may include or omit the matching suffix; the plugin avoids duplicate suffixes. Identify `xlsx` by its ZIP signature.
- After saving, use `schematic.exportPng` to inspect the full page; decode by returned file type. Multi-page output may be ZIP. Background `editor.screenshot` may be stale. If two audit counts differ, wait for topology refresh and check again. Unknown DRC or structural-audit shapes are indeterminate, not a pass.
- `schematic.modifyText` is rejected on EDA 4.1.78 and requires EDA 4.2 or later. Persistence after save on 4.2 has not been confirmed; immediate readback is not proof of saving.

## Repairs and macros

- First inspect label problems read-only, then choose `pruneFloatingLabels`, `fixNetLabels`, `repairNet`, or `dedupeWireNets` as appropriate. Use `dryRun` where supported. `pruneFloatingLabels.dryRun` defaults to cleanup; `fixNetLabels.dryRun` defaults to preview. Check netlist and DRC afterward. Source rewrite is not a routine prerequisite; use it only when explicitly needed and backed up.
- Use `macro` only to combine known steps that need no intermediate decisions. Step results are under `steps`. Stop dependent steps on failure or unknown writes. If the next action depends on readback, submit it separately.

Replacing a complete component is not one ACE command. AI and a person must confirm the substitute, footprint, and pin mapping first. Module-reuse plugin RPC is not an ACE HTTP command. With ACE alone, back up the project, verify resources, pin mapping, nets, and properties; place the replacement, then delete the old component only after all checks pass. Recheck the netlist and non-target objects. The user initiates and confirms PCB update in EDA.

Official netlist references: [legacy string API](https://prodocs.lceda.cn/cn/api/reference/pro-api.sch_netlist.getnetlist.html) and [file API](https://prodocs.lceda.cn/cn/api/reference/pro-api.sch_manufacturedata.getnetlistfile.html).
