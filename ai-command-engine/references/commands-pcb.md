## Receive the Design and Inspect the Current State

The user initiates and confirms schematic-to-PCB updates in the EDA interface. AI must not call `pcb.importChanges` or the official import interface. Before and after an update, use `pcb.listComponents`, `getComponentPads`, and `listNets` to check component identities, footprint associations, per-pad nets, and non-target objects. A successful plugin receipt does not replace saving, reopening, or a whole-board check.

## Board Outline, Layers, and Placement

- Public coordinates for `pcb.drawOutline` use the lower-left as the origin and mil as the unit. Before repeating an outline, inspect the actual primitive type and ID; do not assume it is a Region.
- Check layer count and stackup separately. `setCopperLayers.count` accepts only even numbers from 2 to 32. Read the complete configuration with `getStackingConfig` and read it back after `applyStackingConfig`. Setting the default stackup does not mean it has been applied to the current PCB. Reactivate the PCB after changing custom layers. Do not guess unknown layer names or numbers.
- `getCurrentLayer`, the physical-stackup configuration commands, and the real-time DRC toggles were confirmed unsupported on EDA 4.1.78. They require EDA 4.2 or later; 4.2 has not yet passed host acceptance. See [PCB Less Frequently Used Commands](commands-pcb-low.md#eda-version-restrictions) for each command name.
- After `pcb.moveComponent`, use `checkPlacement` to check clearance. It uses pad bounding boxes and cannot replace checks of component bodies, silkscreen, or mechanical dimensions. Do not report all placement as passing if `complete:false` or objects were skipped.
- Use `pcb.groupBySchematicRegions` when explicitly asked to organize by schematic functional area. First inspect `dryRun`, board-outline capacity, and the sources of dimensions; then execute and read back. It is not the entry point for moving an ordinary single component.

## Checks, Saving, and Manufacturing Exports
