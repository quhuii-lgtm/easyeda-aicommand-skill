# Frequently Used PCB Commands

“Frequently used” refers to recommendations for common board-design workflows, not measured call counts. First check the target window using [Connections and Environment](setup.md). `GET /help?cmd=<command name>` uses the window currently selected by the proxy; confirm that it matches the target version before relying on its parameters. See [Detailed PCB Guidance](commands-pcb.md) for full restrictions. See [Less Frequently Used PCB Commands](commands-pcb-low.md) for specific rules, stackups, and specialized operations.

| Stage | Recommended commands | Purpose |
| --- | --- | --- |
| Inspect current state | `pcb.listComponents`, `pcb.getComponentPads`, `pcb.listNets`, `pcb.listLayers` | Check components, pad nets, and layers. |
| Pad connection method | `pcb.connectComponentPadDirect` | The compatibility entry point is temporarily disabled; calls are rejected before accessing the project or SDK. |
| Placement and outline | `pcb.moveComponent`, `pcb.checkPlacement`, `pcb.drawOutline` | Plan placement first according to [PCB Operating Requirements](PCB操作要求.md), then place components, check clearance, and create the board outline. |
| Routing | `pcb.routeTrack`, `pcb.placeVia` | Plan routing and layer changes according to [PCB Operating Requirements](PCB操作要求.md). The temporary plugin policy requires each `routeTrack` segment to be at least 1 mil (25.4 μm); shorter segments are rejected before writing. This is not an SDK limit. |
| Copper pour | `pcb.pourCopper`, `pcb.listPours`, `pcb.rebuildPour` | Create, inspect, and rebuild copper regions. |
| Checks | `pcb.runDrc`, `pcb.getNetInfo` | Check design rules and target nets. |
| Save and manufacturing | `pcb.save`, `pcb.exportGerber`, `pcb.exportPickPlace` | Save and generate manufacturing files as needed. |

This page covers 18 commands. PCB coordinates and lengths use mil. A `routeTrack` return ID alone does not prove the track was written; rely on primitive readback. See [Detailed PCB Guidance](commands-pcb.md). `pourCopper` creates only a copper boundary; use `rebuildPour` to inspect the actual fill. Do not report a pour as complete when the result is `no-fill`. A DRC result with no errors alone does not prove manufacturability.

The name and parameters of `pcb.connectComponentPadDirect` are retained for compatibility with existing calls. Required parameters are `documentUuid`, `componentId`, and `padNumber`; optional `padId` distinguishes pads with the same number.

The command always throws a temporarily disabled error. `error.cause` is `{ disabled:true, retryable:false, writeAttempted:false }`. Rejection occurs before any project or SDK access, so the call performs no read or write and does not return a `partial` write result.

The command is temporarily disabled because the tested host's public interface cannot reliably read back thermal-relief settings. This does not mean that every setter in the host version is broken. Reassess restoration when a reliable readback interface or official fix is available. The read-only diagnostic `pcb.getComponentPads` remains available; routing, copying sheets, and module reuse are unaffected.

`heatWelding` from `pcb.getComponentPads` is a per-pad, read-only diagnostic. Its statuses distinguish `null`, `config`, `unavailable`, `exception`, and `invalid`. A read exception returns `{status:"exception",error:{message}}`; an invalid return value returns `{status:"invalid",returnedType,reason}`. `config` means only that a configuration was read; it does not prove rule priority or the connection rule actually used by the host.

When `heatWelding.status:"invalid"`, the response also includes `rawFields`, a fixed list of `connectionMethod`, `divergenceSpacing`, `divergenceLineWidth`, and `divergenceAngle`. Each field independently returns `status` and `type`; `value` is returned only for safe scalars. Undefined fields and read exceptions are labeled `undefined` and `exception`. Non-finite numbers include only `finite:false`. Objects, functions, Symbols, and BigInts are recorded by type only; no arbitrary fields are read, and they are not converted or serialized. Each SDK field is read at most once. This diagnostic does not change the invalid-value determination or direct-write behavior.

The optional `_timeoutMs` for `pcb.connectComponentPadDirect` defaults to 290000 ms and has a maximum of 2147483647 ms. Budgets below 1000 ms are treated as 1000 ms.

## Designator and Silkscreen Precheck (v0.20.71 Limited Host Acceptance Passed)

`pcb.modifyComponentAttribute` changes Designator attributes, located by `componentId` or a unique current `designator`. It supports `x`, `y`, `rotation`, `fontSize`, and `visible`; coordinates are mil. It does not renumber the designator and preserves the component position, footprint, and nets. Send only fields to change. Success requires both attribute-getter and full-source checks. It does not save automatically.

The original-design side of `pcb.checkSilkscreen` reads standalone text, designators, and pads through SDK world-space bounding boxes. `minClearance` is in mil and defaults to 0. `potentialConflicts` are box overlap/touch/proximity candidates, not confirmed glyph collisions; `sdkBoxDistanceMil` is not actual silk-to-copper or silk-to-mask clearance. `complete` is always false. Check `checkedObjects`, `coverage`, and `unsupported`; an empty candidate list does not prove board-wide silk compliance. Footprint-internal silk, actual mask openings, complex outlines, and font-stroke edges are not covered by this original-design box check. Editor-hidden layers may still be manufactured. Local regression, expert review, top/bottom designator edits, text movement/side changes, and save/reopen passed for v0.20.71; the stated coverage gaps remain. Call these commands only if listed in the current window's help.

## B3 Hole and Standalone Pad Candidate (Installed-Version Acceptance Pending)

`pcb.placeHole` requires `x`, `y`, `holeDiameter` in mil and an explicit `plated`. `plated:false` without `padDiameter` creates a copper-free mechanical round hole. Supplying `padDiameter` creates a multilayer pad with copper and requires the pad diameter to exceed the hole diameter; `plated:true` requires `padDiameter`. Purely mechanical holes cannot be assigned a net. Select the hole diameter from design requirements and manufacturing capability, not from a screw name.

`pcb.placePad` creates a standalone SMD pad and requires `layer:top|bottom` and `shape:circle|rectangle`. A circle uses `diameter`; a rectangle uses `width` and `height`, with optional `cornerRadius`. It creates neither a component nor a drilled hole.

In EDA 4.1.78, v0.20.86 verified adaptation for default records created with a new net. Creating a PAD may also create the net's default NET and rule records. The plugin accepts only the two records exactly attributable to this request and with confirmed default content; other primitives and existing rules must remain unchanged. Pre-creating the net is unnecessary. New-net ordinary SMD creation and save/reopen passed; copper-hole and partial-mask new-net cases have only local regression evidence.

Optional `solderMaskAndPasteMaskExpansion` uses SDK numeric fields `topSolderMask`, `bottomSolderMask`, `topPasteMask`, and `bottomPasteMask`, in mil. If omitted entirely, source confirms inheritance and the current effective getter values are also returned. Partial objects use the creation-time default snapshot described in v0.20.73; those values are not manufacturing defaults. Explicit values are checked against source and getter. `solderMaskOpen` is unsupported. For checked multilayer solid-circle mechanical holes only, a requested line width of 0 saved as 1 by the host is accepted as a reported representation difference; center and radius must still match. This exception does not apply to arbitrary Fill paths. `manufacturingExportVerified:false` means this call did not export manufacturing data; historical fixture exports cannot replace checking the current object.

Before success, read new objects by ID and check complete source. Host ticket renumbering is allowed and reported; arbitrary changes to non-target primitives or rules are not. The command does not save, run DRC, or export manufacturing data. On an uncertain write, retain created IDs and stop without adding a replacement, deleting, retrying, or keeping later independent requests locked. Formal installed-version and save/reopen acceptance for all shapes remains pending.

## Rounded Corners and Complete Partial-Expansion Writes (v0.20.73 Limited Host Acceptance Passed)

Rectangle `cornerRadius` is in mil from 0 to half the shorter side. On the verified host, SDK radius is a percentage of half the short side, so the plugin sends `200 × cornerRadius / min(width,height)` and returns `requestedCornerRadiusMil` and `sdkRadiusValue` separately. Do not interpret the SDK number as mil; manufacturing checks must inspect the used corner aperture and position, not just getter/source.

Omitting `solderMaskAndPasteMaskExpansion` or passing `{}` selects host inheritance. Supplying all four fields uses them directly. For a partial object, the plugin creates the pad in inheritance mode, reads its four effective values, merges requested fields, then changes expansion on that same new ID. It returns `mode:explicit-with-default-snapshot`, original `requested`, `defaultsReadback`, final `applied`, and `defaultedFields`. Missing fields become creation-time fixed values; the plugin neither guesses defaults nor converts null to zero. Check primitive identity, geometry, source, and other records after creation, before modification, and after modification. If defaults are incomplete, state changes, or modification is uncertain, stop without resending or deleting. Failure receipts retain ID, stage, and values obtained. Success does not prove saving or manufacturing checks.

An EDA 4.1.78 isolated trial read defaults from the getter, retained remaining values after top-side override, and retained all four values after save/close/reopen; a 40 mil circle with 3 mil top expansion exported a 46 mil opening. This is not official-command acceptance or proof of future rule evaluation or other-version corner semantics.

## Manufacturing-Layer Silkscreen Check (v0.20.75 Limited Host Acceptance Passed)

`pcb.checkSilkscreen` returns original-design bounding-box candidates plus a separate `manufacturing` check, without editing, saving, or clipping silk. Original `potentialConflicts`, `checkedObjects`, `unsupported`, and `coverage` retain their meaning; top-level `complete` stays false and does not confirm actual glyph/mask collisions. The manufacturing check uses this run's official top/bottom silk Gerbers, same-side mask openings, and supported outlines. Footprint silk and fonts use exported coordinates; bottom silk is no longer mirrored. Confirmed findings and numeric-boundary candidates are separate; `minClearance` is caller-specified mil, not a board-house rule read from the host.

The first parser supports verified absolute millimeter coordinates, circular-aperture straight strokes, circle/rectangle/confirmed-round-corner macro flashes, filled regions, and ordered draw/erase. Circular approximations disclose inner/outer error, and near-boundary candidates are retained. Unknown commands/macros, arcs, or unclear outlines mark the layer incomplete. The initial board-edge parser covers one clearly identified simple closed straight outline and checks outside-board and clearance; multiple outlines, slot roles, and complex curves are unsupported. Outline stroke width is not the board-material edge. Host output may already clip silk, so no manufacturing finding does not prove original-design clearance. Merged layers cannot recover individual source IDs or collisions between silk objects; `manufacturing.complete` describes only the listed layer parse/check scope.

## Manufacturing Profile and Order Comparison (v0.20.77 Candidate; Installed Acceptance Pending)

The v0.20.77 candidate checks a source-attributed JSON manufacturing profile with `pcb.checkManufacturingProfile`. The command accepts the contents of a `profile` object, not a local file path; optional `orderConfirmation` holds actual order confirmation. Follow current-window help. ### Specified-Path Differential Routing (v0.20.79 Candidate and Limited Acceptance)

`pcb.routeDiffPair` builds two coupled tracks from a center path. Check current-window help. `pair` must explicitly contain `{positiveNet,negativeNet}`, and both different nets must exist. `path`, `width`, and `gap` use mil; `gap` is copper-edge distance, so centerline spacing is `width+gap`. The positive track offsets along path direction's numeric normal `[-dy,dx]`, and the negative offsets oppositely. Visual left/right depends on coordinate direction. Reversing the path swaps their physical sides but not input net names.

Use `dryRun:true` to preview; omitted or false executes the write. A selected layer must be an enabled SIGNAL layer. Only geometric duplicate consecutive points and same-direction collinear intermediate points are removed; input is not snapped or lengthened. The minimum generated segment remains 1 mil. Reversal, self-contact, insufficient spacing between any positive/negative segments, or unreliable numeric geometry rejects the entire pair before writing. Both sides share the document and time budget. Read back each segment and check final source coverage, non-LINE records, and rules. A mid-write failure returns `partial`, completed sides, and failed-candidate evidence, then stops. Timeout does not cancel the host; do not resend, delete, or roll back. Later independent commands are not persistently locked.

`plannedLengths` describe only the planned paths, not measured full-net length; corner-induced length mismatch is returned. The command does not auto-route around obstacles, tune length, connect duplicate pads, create differential rules, or save. After success, separately check actual connectivity, whole-board DRC, reference planes, and length mismatch. Creation success does not establish impedance. JSON example:

```json
{"cmd":"pcb.routeDiffPair","params":{"pair":{"positiveNet":"USB_DP","negativeNet":"USB_DM"},"path":[[100,100],[300,100],[500,300]],"width":6,"gap":4,"layer":"top","dryRun":true}}
```

The example values only illustrate parameters, not USB design values. Production width/gap must use one sourced stackup/calculation record and be checked against rules and the actual order. Set differential length tolerance from the specific interface; do not default to 10 mil.

### Length Tuning (v0.20.80 Candidate; Installed Acceptance Pending)

`pcb.tuneLength` adds length to an open track chain inside a specified region. `net`, `targetLength`, and `region:{xMin,yMin,xMax,yMax}` use the current PCB and mil coordinates. `targetLength` is the selected chain's total centerline length, not the sum of every branch on the net. Use `primitiveIds` to select an explicit open chain of unlocked tracks with the same net, layer, and width. If omitted, `net` and `region` must fully contain one unique candidate straight segment. Optional `tunePrimitiveId` selects the segment to tune; only that segment is replaced while other selected segments stay. The region bounds the new copper, and both ends of the tuned segment must be fully inside it.

Preview with `dryRun:true`; omitted or false writes. `side` may be `auto`, `left`, or `right`, relative to the path ordered by endpoint coordinates; the positive normal is `[-dy,dx]`. `auto` tries both sides and available tuning segments. Failure to find the current serpentine family is a reported reason, not proof all shapes are impossible. Prefer applicable project rules under D12. The SDK has no reliable local-serpentine tolerance/self-spacing readback, so explicitly supply `lengthTolerance` and `minSelfGap`. The former bounds total-length error; the latter is copper-edge spacing between nonadjacent segments involving new serpentine, not a new requirement for two unchanged old tracks. Do not substitute differential gap, a 10 mil differential default, or net-relative length tolerance. The 0.001 mil geometry-readback tolerance is separate from total-length tolerance. `parameterSources` explains explicit values and unconfirmed rule mappings; it does not claim values were obtained from the project.

If target is already within length tolerance, return `changed:false` with no write. If target is shorter and outside tolerance, return an explicit error. Generated tracks retain the 1 mil minimum segment. If an existing track has a branch, pad, or via mid-segment, confirm the connection will remain or identify it and the reason for rejecting before writing. Do not guess for special shapes, cross-layer bounds, or unclear actual pour contact. Execution creates/readbacks the new local path first; confirms original tracks and non-target records; then deletes the explicit old tuned segment; and finally checks enumeration, source, and actual total length. Failure may return `partial`, new IDs, deletion attempts, and old-bypass state; unknown means not confirmed. Stop relying on that result; do not retry, roll back, or save automatically. Later independent commands are not persistently locked.

Planned/actual length applies only to the selected chain. Report actual minimum spacing without clamping it to the request. Success does not pass whole-board spacing, connectivity, impedance, or manufacturing. Type-C repeated-pad branching and autorouting integration were to be developed separately. Example: select a 200 mil test line, target 220 mil, explicitly set `lengthTolerance` and `minSelfGap`, then preview; these test values are not USB/DDR/interface defaults.

### Serpentine Revision to Circular Arcs (v0.20.81–v0.20.83)

The user explicitly requested circular-arc serpentine. v0.20.81 uses real LINEs and tangent ARCs, not tiny straight segments to imitate arcs. The 23 v0.20.80 results remain evidence only for old triangular polyline geometry/save; arc style needs separate acceptance. Existing inputs remain `net`, `targetLength`, `region`, `primitiveIds`, `tunePrimitiveId`, `side`, and `dryRun`. New required `bendRadius` is mil centerline radius. Prefer confirmed applicable project rules; because current SDK has no verified local-serpentine radius/tolerance/self-spacing mapping, supply `bendRadius`, `lengthTolerance`, and `minSelfGap` explicitly and return their sources. No general production radius or default 10 mil differential gap is assumed.

Each rounded U cell has four 90-degree arcs, return legs, and a top straight; it must replace the full segment without a lead-in overlapping the old baseline. Search the number of cells at fixed radius; omit zero-length straights, and apply the existing 1 mil minimum to nonzero short primitives. If radius, space, spacing, and requested added length are incompatible, report an error rather than silently changing radius or reverting to polyline. Total length includes true arc length. Arc apex, swept-angle extrema, and half-width count toward region bounds. Sampling chords with a sagitta error bound are used only for contact checks and are never written to PCB. Check return spacing on the analytic curve family separately from existing connection protection; do not falsely reject construction pieces of adjacent corners as independent branches.

Create/read back each LINE/ARC primitive. Check ARC type, endpoints, sweep direction, radius, and true arc length; valid reverse storage must swap endpoints and reverse sweep together. Use actual readback curves in planned direction and retain readback deviation. Only after new path and old-data preservation are confirmed, delete the explicit old tuned segment and check source, both SDK enumerations, rules, and total length. `dryRun` returns real primitive plan and sampling scale, not a huge set of tiny calculation chords. Success distinguishes planned versus source-readback serpentine-family spacing lower bound; it is not the whole chain/board measured minimum and does not compare two unchanged old tracks.
